## 0. 一句话模型

**运行方案管「测什么、测多狠」（场景的执行策略，固有于场景 → 挂场景）；
执行配置管「在哪、以谁、带什么业务参数」（场景的外部支撑，跨场景
共享 → 挂人/组）；凭证、地址的值由池和表在下层解析；执行快照在底层
兜底复现。**

一条公理贯穿：**内容侧与上下文侧不得共用一个配置容器**——共用时要么
灵活性不足（全配在组级，无偏移出口），要么操作量过大（全配在本次，
每次全选）。

命名公理（2026-11-11 裁定）：**外层叫「配置」，内层保留「方案」**——
「方案」一词完整让给场景内部的运行方案（既有概念全线不动），外部
支撑定名**执行配置**。

## 1. 背景与决策记录（审计轨迹）

现状：运行方案（`composer_run_schemes`）是场景级对象，但 payload 同时
装着两类 scope 不同的东西——上下文侧的 `serviceBindings`（绑定覆盖）、
`environmentId`，与内容侧的 `dataSetSelection`、`step_from/to`、
`n_runs/parallel`。后果：「一组用例的通用选择」没有跨场景载体（N 个
场景配 N 遍）；易变项与稳定项混装、选择成本虚高；数据集/步段为场景
私有 ID，与可共享项混装导致「方案能否跨场景复用」长期纠缠。

演化路径（含三次有意识的推翻/修正）：

1. **变化频率分层** → 确认现状其实已分层：carry/凭证结构性不在方案
   值域内，方案独占的只有策略+数据+绑定覆盖；
2. **方案模板** → **被推翻**：出生模具引入拷贝/引用两难，且只解决
   「建方案成本」不解决「执行时选择成本」；
3. **个人跑法 = {策略+环境+绑定}** → **被修正**：策略（次数/并发）
   是测试设计的一部分，归场景侧，不随「谁在跑」变；
4. **内容/上下文分界** → 定稿：内容侧归运行方案；上下文侧归执行
   配置——运行时链位，派发时解析、快照留终值（推翻 2 的根因消失）；
5. **命名** → 定名**执行配置**（外层叫配置、内层保留方案）。撞词
   检查：「运行配置」已被方案内策略段占用（`SchemeRunConfigSection`）
   弃；「环境配置」与「环境与地址」管理面软冲突，作备选；
6. **服务信息管理更名「服务配置」** → 0047 瘦身后该页只剩别名注册
   表（含槽位声明）+ carry 服务轴视图，原名承诺大于持有物。路由
   `/service-admin` 不动。注记：carry 双轴皆合法（服务轴=此页，层轴
   =公共项目/项目配置页签），不得互删；
7. **carry 变体 → 初裁套装引用式，同日修正为内联子配置式** → 初裁
   （独立 carry 套装对象，carrySetId 引用）**被推翻**：实际结构是
   **执行配置本身按系统分组**——多系统混合编排下，一个用户保存多组
   配置，每组内含多组子配置（每被测系统一个）。carry 覆盖**内联**于
   子配置，套装对象撤销；「个人/项目多套」由执行配置 user|project
   两 scope 天然覆盖。薄束性质精化：**零凭证值、零地址值**，carry
   业务参数值允许内联。守则：项目区不吃**个人**执行配置的 carry
   覆盖（项目 scope 配置的覆盖在项目区合法生效）；集成/定时不吃
   执行配置。代价明记：跨配置字段复用靠「复制配置」；环境仍全局
   一个（混环境编排另议）；
8. **个人 carry 层退役，收编为默认执行配置的覆盖** → 个人层与默认
   执行配置双轨撞车（两个「我的缺省 carry」，解析上后者恒压前者）；
   收进服务配置（Admin+）则上交治理权、扼杀变体。裁定：carry 值
   全平台**三个家**——公共项目层（全局默认）/ 项目层（项目默认）/
   执行配置覆盖（个人默认=默认配置 + 业务变体=命名配置；项目变体=
   项目 scope 配置）。**个人层不再存在**；存量一次性迁入默认执行
   配置，迁后停读、不做双源回落。终局：「我的配置」页退役（三卡
   全迁：env 偏好收编 + carry 个人层收编 + 漂移面板迁执行配置详情），
   个人设置保留 account/tokens/card，个人执行配置唯一入口 `/exec-configs`；
9. **项目区个人 carry 覆盖：默认不吃、显式吃（精化决策 7 守则）** →
   「项目区不吃个人覆盖」的两个极端出路皆有代价（挪私有区=复制漂移；
   无条件提升=成员默认配置静默改写项目内容）。裁定镜像环境链既有
   模式（项目默认压个人偏好、本次显式压一切）：**默认个人配置的
   carry 覆盖不参与项目区**（默认执行全员一致）；**显式选定的个人
   配置覆盖在项目区手动执行时生效**（显式选择、执行人负责）。安全
   护栏：预览 source='exec_config' 明示偏离；快照记 execConfigId
   留痕；集成/定时仍不吃执行配置（同指纹不变量不经此路）。可选
   治理开关（项目管理员禁个人覆盖）暂不做，等治理诉求出现再议。

## 2. 层级总览与各层配置过程

**六个层级，每层一个职责、一个宿主、一个入口——不重叠、不缺位：**

| 层级 | 宿主 | 配置过程（谁·在哪·配什么） | 产出（执行时的角色） |
|---|---|---|---|
| **平台·名词层** | 注册表/定义表 | Admin+ 在**服务配置**登记身份面（名字→目录服务+凭证槽位声明）；在**环境与地址**定义环境（名/版本线/默认）并维护 (目录服务,环境)→地址 | 解析锚点：面/槽位缺省、env_id 供给、地址矩阵 |
| **公共项目层** | 公共项目 | Admin+（公共项目管理门）在公共项目「配置」页签配 carry 全局默认 | carry 兜底值（全局默认） |
| **项目层** | 项目 | 项目管理员在项目「配置」页签：默认环境（环境链位③）、项目层 carry、**项目凭证池**、槽位状态；（组级批次）项目 scope 执行配置=项目变体 | 环境链位③、项目池、项目 carry 默认与变体 |
| **个人层** | 人 | 全员在**执行配置 `/exec-configs`**：多组配置（一套默认+若干命名；新建可复制）；在**认证管理 `/auths`**：个人凭证池 | 环境链位②/④载体、槽位覆盖、carry 个人默认与变体、个人池 |
| **场景层** | 场景 | 作者在编排器写步骤引用（服务·身份面）；场景显式 carry 覆盖；在方案工作台存多份**运行方案**（数据/步段/强度） | 引用源（名词）、carry 顶位、策略 |
| **当次层** | 执行 | 执行人在**执行面板**：选 场景+方案+执行配置，临改环境/策略（绑定不开放） | 链位①（本次） |

层间关系只有三种动词：**登记**（名词层）、**设默认**（公共项目/项目/
个人默认配置）、**选变体**（命名配置/方案/本次）。每层的「默认」住在
本层，「变体」永远从下层选——这是「灵活性 × 操作量」两难的解。

## 3. 内容/上下文分界

| 配置项 | 归属 | 说明 |
|---|---|---|
| 数据集组合 / 步段 / 次数并发 | **内容侧（运行方案）** | 数据与强度是场景内容；同场景多目的靠多方案 |
| 环境 | **执行配置** | 上下文（全局一个） |
| 绑定（身份面→槽位） | **执行配置**子配置 | 上下文（身份选择） |
| carry 字段覆盖（按系统） | **执行配置**子配置内联 | 业务过程变体 |
| 凭证值 | 池（个人/项目） | 不进执行配置——由池按 (system, env, slot) 解析 |
| 地址 | 部署表 | 不进——由 (目录服务, env) 解析 |
| carry 默认值 | 公共项目层 / 项目层 | 个人层已退役（决策 8）；个人默认=默认执行配置 |

「场景的执行策略」三段分工：**运行方案 = 留存的命名策略**；**本次
临改 = 当次偏移**；**执行快照 = 复现基线**。

## 4. 执行配置对象

**结构（按系统分组的子配置）**：

```
用户/项目
└─ 执行配置 × N（一套默认 + 若干命名；新建可自现有配置复制）
   ├─ name / isDefault
   ├─ envId（全局一个环境 → 各系统地址派生展示，不存储地址）
   └─ systems[]（每个被测系统一个子配置）
      ├─ bindings: 身份面 → 槽位（可多条 = 一组服务）
      └─ carryOverrides: {字段: 値}（该系统在此业务过程下带的参数）
```

**零凭证值、零地址值**；carry 业务参数值内联。性质：不含凭证值
（池隔离不破）；跨区可移植（槽位是名字——「商户B@UAT」私有区跑解析
个人池、项目里跑解析项目池，引用不用换）；地址自动跟随（env 换 →
地址/凭证环境维度/版本线联动）。示例：「商户B视角@UAT」= env UAT +
fin 系服务 → 槽位 `merchant-b`——这也是「同域多用户多组匹配」的命名
载体（匹配键是槽位四元组 `(池, system, env, slot)`，域名只是解析结果）。

**scope 与批次**：一张表两个 scope（`user` / `project`），模型同构；
**v1 先落 user**（个人默认+变体），project scope（项目变体，编辑面在
项目「配置」页签）随组级批次落地——这是实施批次划分，不是模型差异。

**与别名不可互替**：配置的 bindings 就是 `{别名 → 槽位}`——配置引用
别名，替代即自引用。别名是平台共享的绑定锚点（场景步骤引用它，共享
场景对全员可跑）；一次执行 = 1 配置 × N 别名，乘法关系。别名行零值
（名字/目录服务/槽位声明/kind）；槽位绑定里的 url 是登录/拨测地址，
与服务 base_url 两回事。槽位解析序：**别名声明（缺省）> 执行配置
绑定（覆盖）> 池内同槽默认行（最终账号）**。

**别名降位为注册表内部键**：「别名」术语从用户词汇表退位（编排器/
执行配置呈现「服务 + 身份面」），但**面的声明必须留在共享注册表**，
不得内联进个人配置包——场景是共享对象，其引用键必须平台共享（hosts
检验）；注册表面同时是缺省层（「选场景直接跑」零前置配置的前提）。

**入口**：侧栏置顶组「通知」下方独立入口 `/exec-configs`（全员——
置顶组语义=高频个人入口；不放「服务」组避免与 Admin+ 管理面混层）。
「我的配置」页随决策 8 退役。

## 5. 执行注入管线

派发时**一次解析、逐链求值、物化落快照**。子配置通过三条链注入被
执行的场景：

| 注入目标（物化产物） | 来源链 | 执行配置的落点 |
|---|---|---|
| `env_id`（→ 快照 environmentId） | 环境链（见下） | 配置的 **envId** 占链位②/④ |
| `config.services`（每服务 URL） | 步骤面引用 → 目录服务 → 部署表[(目录服务, env)]；私有区可 ②步骤直连，项目/公共强制 ③，缺口=引擎报错 | envId 决定取哪行地址 |
| `config.users`（每身份凭证：登录地址/账号/密码/account_fields） | **区定池**（私有区=执行者个人池 / 项目区=项目池）→ (system, env, slot) 命中 → 同槽默认行 | 子配置 **bindings** 覆盖槽位 → 改变池内命中哪条 |
| 步骤字段（carry 注入） | 场景显式覆盖 > **配置内该系统 carryOverrides**（精确命中，缺键回落）> 层序合成（公共项目层 < 项目层；键：面键>目录服务键>层默认） | 子配置 **carryOverrides** |
| 数据集 | 方案 dataSetSelection | — |
| 强度（n_runs/parallel/步段） | 本次临改 > 运行方案 > 场景默认 | — |

四条选择链全文：

```
环境:  本次 > [选定执行配置 │ 方案.environmentId(存量)] > 项目默认
            > [默认执行配置 │ 个人偏好 run.environment(存量回落)] > 平台默认
            （│ = 同位二选一，左侧优先；选定配置遮蔽方案存量，默认
              配置遮蔽旧偏好）
绑定:  选定执行配置 > 方案遗留 serviceBindings(存量兼容)
            > 场景 authored > 池默认行(is_default)
carry(私有区):  场景显式 > 选定或默认个人配置的覆盖 > 公共项目层
carry(项目区):  场景显式 > 显式选定的个人配置覆盖(仅显式,决策 9)
                > 项目 scope 配置覆盖 > 项目层 > 公共项目层
                (默认个人配置不参与)
强度/数据/步段:  本次临改 > 运行方案 > 场景默认
```

**守则（注入正确性的边界）**：

- **区规则**：池按对象所在区二选一（私有=个人池/项目=项目池）；项目区
  不吃个人执行配置的 carry 覆盖——决策 9 精化为「默认不吃、显式吃」；
  公共副本
  不可执行，fork 后走私有区规则；
- **入口排除**：集成/定时跑不吃执行配置（「同一模板全订阅者同一
  指纹」不变量），恒项目凭证；套件显式环境整图生效、策略逐单元；
  预览与执行同源（`resolve_effective_config`）；
- **临改边界**：本次临改只开环境/策略，**刻意不开放绑定**（执行时换
  绑定=换登录身份，误操作跨账号写数据）；
- **失败可见**：缺槽=预检拒绝（提示应指向 `/auths` 预填直达）；缺
  地址=引擎显式报错；预览逐值带来源（`source='exec_config'` 等必须
  能自证每个值的来路）。

## 6. 共享传递公理：引用随行，值不随行

个人差异安置在**选择层**，不在**名词层**；共享场景传递名词与引用，
值由接收区的池按治理规则填：

| 共享路径 | 槽位关联（引用） | 凭证值 | 模式 |
|---|---|---|---|
| 私有→他人（分享/复制） | 随行（方案 authAlias 绑定原样拷贝） | 接收者个人池自填 | 空缺 + 个人填值 |
| 私有→项目（晋级） | 引用随行；槽位绑定不随行（凭证跟人走） | 项目池（r5-2.2 治理） | 空缺 + 项目池 |
| 私有→公共（发布） | strip="always" 剥敏感列；副本不可执行 | fork 者私有区→个人池 | 全空缺 |

值的「携带」唯一合法形态 = 项目凭证池；裸值内嵌已被 `run_materialize`
的 built_in_users 丢弃规则封死（作者明文经导出/套件/订阅外泄的教训，
不得为便利重开）。「分享时清空凭证」实为**无物可清**（凭证结构性
不在场）——比「平时内嵌+分享时清洗」强得多，**不得降级**。不随行
理由分层：硬禁令只覆盖**凭证族**（凭证值+account_fields+登录地址）；
服务地址结构性不在场景；authored 直连地址剥离由**区语义**驱动；
carry 值经晋级裁决 `use=source` 有治理化携带通道；内容本体随行。
**待验证暗角（实施③前核）**：① 发布 strip 是否扫到数据集内容
（手滑藏密码→公开发布即泄漏）；② 晋级对 authored 直连 URL 是阻断
还是转换。

## 7. 快照、复现与存量兼容

- 派发时解析，快照记 `execConfigId + 终值`；重跑回放终值——配置后改
  不影响历史执行（与方案引用同语义）；
- `run.environment` 单值偏好在 v1 收编为默认执行配置的环境字段
  （读侧兼容：无默认配置时回落旧偏好）；个人 carry 层一次性迁入
  默认执行配置（按系统分组），迁后停读；
- 现有运行方案的 `serviceBindings`/`environmentId` 继续按「方案遗留」
  链位生效，不迁移不清洗；新建方案的编辑器把绑定/环境区改指执行
  配置（字段保留兼容）。纯增链位，无强制表结构迁移。

## 8. 执行配置页 = 关联枢纽（关联而非纳入）

解耦在 0044/0047/池/层既已完成，执行配置对既有配置面只做**关联**——
存引用键 + 放深链，不搬数据、不代管维护面与权限门。页内四路关联：

- **环境** → 所选环境地址就绪度（部署表读面）+ 深链「环境与地址」；
- **绑定槽位** → 逐条显示个人池绑定就绪情况，缺失深链
  `/auths?system=…&env=…` 预填直达；别名深链别名详情；
- **服务** → 深链服务配置（Admin+ 写面/普通用户只读指引）；
- **carry 覆盖** → 子配置内联展示各系统覆盖值 + 漂移检查项（面板自
  「我的配置」迁入）；未覆盖字段注明「按层序合成」+ 深链公共项目/
  项目层宿主页。

生效预览复用 EffectivePreviewDialog 的 pickable 形态：选定配置即预览
逐值带来源。全部由现有读 API 拼装，零新后端。

## 9. 服务配置页改造（配套）

原则：**页面重定位 + 术语降位，数据模型零改动**。「服务信息管理」
重定位为「**服务接入治理面**」；术语映射：别名→**身份面**（`服务 ·
后缀`）、无后缀别名→**默认面**、声明槽位→**凭证槽位**、基础服务→
**目录服务**；alias_name 仍是数据键与 URL 键。

- **列表页**：树保留；主表=身份面清单（面名/槽位/kind/**地址就绪
  列**，点缺口跳「环境与地址」聚焦）；「服务级默认」行归位为「默认
  面」首行；登记表单统一（目录服务+面名+槽位+kind，校验原样）；
- **详情页**三 tab：**概览**（面信息+地址就绪矩阵+接入检查清单——
  治理端就绪度，与执行配置枢纽的个人端就绪度成两半）；**字段默认值**
  （carry 层摊开+按层分权：全局层在此可改，项目层只读+深链宿主页）；
  **凭证**（?tab=credential 反查保留+个人池情况+预填跳转）；
- **不动**：数据模型/路由/权限门（ops.write）/校验/导入链；编排器
  选择器同步换术语（显示「服务 · 身份面」，绑定数据仍 alias_name）。

## 11. 与既有体系对齐 + 全景

- 个人覆盖层归一（决策 8 终局）：个人凭证池（/auths）+ 执行配置
  （环境/绑定/carry 覆盖，唯一入口 `/exec-configs`）；「个人永远是
  覆盖层，从不 owning 基础设施」公理不变；生效预览是链位的安全网；
- **交互面四组**：治理面（服务配置=名词+全局 carry；环境与地址=
  env+地址矩阵，**读全员/写 Admin+**——地址透明、凭证隔离）；个人面
  （认证管理=个人池；执行配置=env+绑定+carry 覆盖）；项目面（项目
  「配置」页签=默认环境+项目层 carry+项目池+槽位状态+项目令牌）；
  内容面（编排器=引用；方案=策略）；执行面（面板=当次输入；预览=
  同源彩排）；
- **三条不变量**：名词共享选择个人（换人跑不变形）；引用随行值不
  随行（凭证结构性不在场）；每个值恰一个权威源（地址=部署表、凭证=
  池、carry=层与配置覆盖、策略=方案、env=链）。

**一句话终稿：名词在注册表、值在池和层、选择在配置、策略在方案、
当次在面板；派发一次解析、快照终身复现。**
