# GIMBAL 执行能力功能点与归属（2026-09-24 梳理）

## 设计原则（本轮定稿）
- 线性过程在 step；流程控制在外层编排（执行器 / suite）；作用域用上下文（固定四层，不加深）；特殊能力用策略。
- 业务语义 → 策略 / scenario / plate（需评审的事实源）；测试活动语义 → 执行指令 + 执行器控制层（按需组合，不进 scenario）。
- 类比：plate = 类型声明；step = 方法调用；scenario = 函数体（线性）；输入输出 = 函数签名（consumes/produces）；上下文 = 栈帧；句柄 = 资源描述符；suite/执行器 = 主程序与运行时；依赖图解析 = 链接器。
- 平台与 CLI 只是入口，不各自实现执行逻辑。
- 不做：运行时条件分支、scenario 内循环、手写 goto（续跑用区间执行 + 输入注入替代）。

## A. 业务过程 —— 策略 / scenario
| # | 功能点 | 落点 |
|---|---|---|
| A1 | Extract 导出标记 → scenario 输出（produces） | 策略（Extract） |
| A2 | 输入推导（开头引用、内部未 extract 的变量 → consumes） | 执行器编译/预处理期推导 |
| A3 | 前置条件声明（按能力声明，不写死 scenario id） | scenario setup；能力语义对齐 plate produces/consumes |
| A4 | 多角色：step 级凭证/身份选择 | 认证策略扩展 |
| A5 | 反向与幂等：错误码断言、同一步重复调用 | 断言策略 / 调用策略 |
| A6 | 轮询等待（异步、最终一致） | 策略（循环在策略内部，带超时与间隔） |
| A7 | 句柄获取：SSH、本地 shell、DB、MQ 等 | 策略 + ResourceManager/provider（已有底座） |
| A8 | 阶段内顺序（同阶段多个策略的 order） | 策略字段；阶段间顺序由状态机固定 |

## B. 控制过程 —— 执行器控制层（可借策略插槽注入）
| # | 功能点 | 落点 |
|---|---|---|
| B1 | 断点策略 + 结构化输入（格式由 gimbal 声明） | 控制注入策略；默认只作用于本次执行 |
| B2 | 调试会话控制通道（继续/单步/改值/终止） | 执行器 server 模式 |
| B3 | 策略来源区分（业务声明 / 控制注入），保存、导出、评审只看业务 | 策略 schema |
| B4 | 区间执行 step_from / step_to | 执行器驱动（step_from 当前未生效） |
| B5 | 检查点：保存第 k 步输出 | 执行器 |
| B6 | 续跑 = step_from + 检查点输出注入 | 执行器（复用 B4 + B5，无需 goto） |
| B7 | 句柄可重建 / 不可重建声明，续跑起点自动判定 | resource provider + 执行器 |
| B8 | 重复与并发（nRuns / parallel / retry）从平台下沉 | 执行指令 + 执行器 |
| B9 | 执行模式分派（mode）+ 驱动注册 | 执行器（沿用 StrategyExecutor / PluginLoader 注册方式） |

## C. 组织层 —— suite / 执行器组织
| # | 功能点 | 落点 |
|---|---|---|
| C1 | 用例拼接 | 执行器组织 / suite |
| C2 | 1:N 前置扇出（前置输出 → N 个尾部输入） | 执行器组织 / suite |
| C3 | 组合覆盖（全组合 / 配对 / pairwise） | suite |
| C4 | 并发竞争（N 个子执行打同一实体） | suite / 执行器 |
| C5 | 造数复用（输出持久化 + 有效期） | 执行器统一接口；存储：平台（值归平台）/ CLI 本地文件 |
| C6 | 依赖图：由 consumes/produces 自动推导，拓扑排序、菱形去重、循环检测、多生产者歧义需显式指定 | 声明来自 plate/scenario；解析在执行器/suite；后置实现 |
| C7 | suite 收集执行（单位 = scenario + 执行指令）、选择器 | suite |

## D. 跨组件契约
| # | 功能点 | 落点 |
|---|---|---|
| D1 | 执行指令结构（plan：mode、区间、次数、并发、数据集、扇出、断点等） | 定义归 plate（过渡期 gimbal schema）；平台 RunScheme 存实例；CLI `--plan` |
| D2 | 事件结构（版本号、序号、执行/步骤/分支三级标识） | 执行器定义；平台、报告、Agent 消费 |
| D3 | 句柄描述结构（描述可序列化，实例运行时重建；上下文只放引用） | schema Resource + ResourceManager |

## E. 入口与平台
| # | 功能点 | 落点 |
|---|---|---|
| E1 | CLI 补全：--plan、调试、续跑、导入导出，旧参数映射为 plan 快捷写法 | 执行器 CLI（按 task 5 注册约定） |
| E2 | 触发 / 定时 / CI（任务来源） | 执行器能力；平台侧入队 |
| E3 | PG 队列（FOR UPDATE SKIP LOCKED）替换进程内调度与取消注册表 | 平台执行链 |
| E4 | SSE 推送（Last-Event-ID 续传、LISTEN/NOTIFY 或读事件表） | 平台 |
| E5 | 台账增加分支维度（1 前置 + N 子项） | 平台存储 |
| E6 | 报告：事件投影 + 定制筛选/渲染；导入外部事件日志（CLI/Jenkins 结果） | 投影定义在执行器；展示与导入在平台 |
| E7 | 安全：本地 shell 平台侧默认关闭、命令白名单、审计事件；命令参数 shell 转义 | resource provider |

## 建议实现顺序
1. 契约先行：D1 执行指令、D2 事件结构、D3 句柄描述
2. 业务签名：A1 导出、A2 输入推导
3. 控制基础：B4 区间、B5 检查点、B6 续跑、B9 模式分派、B8 下沉
4. 调试：B1、B2、B3，平台 E4
5. 组织：C2 → C1 → C4 → C3 → C5 → C7，平台 E3、E5
6. 报告与导入：E6；CLI E1 随每步补齐
7. 依赖图反推：A3 声明可先定，C6 解析最后做
