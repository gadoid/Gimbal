## 0. 一页速览

**做什么**：新增「账户组合」对象——一组**服务 → 已登记身份条目**的映射，个人或项目持有、跨场景复用；场景在 `config.accountCombo` 侧键**引用**绑定一个组合；执行时组合作为各装配面绑定合并的**垫底层**（最基础默认），改动传播到所有引用场景。

**解决什么**：身份配置按场景重复劳动——注册制已把"服务-实例-身份-凭证"收口，但"哪个服务用哪个身份"仍散落在最细的步骤级直引；运行方案 `serviceBindings` 是正确的场景级面，之上缺跨场景复用层。

**顺带退役**：执行配置页语义旋转（0 使用的运行期换用载体），壳保留改绑组合端点；Runner 下拉移除。

**五条主轴**（详细论证见对应节）：

| # | 主轴 | 节 |
|---|---|---|
| 1 | 引用语义：场景绑组合、执行活引用、改动传播 | §2/§6 |
| 2 | 解析序五层，组合永远垫底，不重排任何面内覆盖序 | §3 |
| 3 | 组合零池规则：池仍由 `credentialSource` 链决定，组合不碰 | §3.4 |

## 1. 背景与问题

### 1.1 现状缺口

服务-实例-调用身份-凭证全线注册制（要么新建即注册，要么选用已注册内容），但**"哪个服务用哪个身份条目"散落在最细的面**：

- 编排器 F4 流程把身份选择推到**步骤级直引**（选已登记条目 → 就地注入 `${auth.X.token}`）——每场景每步重选；
- 架构里正确的**场景级**默认面（运行方案 `serviceBindings`：服务 → 身份条目）埋在方案工作台，之上没有**跨场景**复用层。

核心痛点：权限/身份配置是按场景重复劳动。需要可管理的**多系统账户组合**——场景绑定一次即得默认身份映射，组合改动集中传播，整套身份一键切换。

### 1.2 执行配置页退役证据（讨论中核实）

| 维度 | 事实 |
|---|---|
| 可选入口 | 仅 Runner 页一个下拉（`Runner.vue:231-239`）；场景/编排器运行弹框、套件、集成都选不了；令牌/图/临时执行携带即 409 |
| 线上使用 | 库中 3 条配置、0 条默认；**300 次执行 0 次**带 `execConfigId`（后端只要选了就写快照，0 可信） |
| 每次执行实际带的 | `serviceBindings` 300/300——"以谁的身份跑"的真正载体是运行方案 |
| 页面史 | 11-18~11-19 六轮重设计（v2~v6）；每轮后对象更窄：carry 写面退场 → 环境字段删除（0060）→ `aliases` 圈定"执行链不消费" → 项目池撤下 |
| 历史功能去向 | 环境=身份标签链；carry=五张维护面；就绪度=服务注册页；生效预览=三处多宿主 |

**结论**：问题不在页面形式（六轮已打磨成理想工作台），在对象语义（运行期换用载体，无人消费）与消费方式（Runner 下拉，选了才生效）。**壳保留，语义旋转**（§8.2）。

### 1.3 目标与非目标

**目标**：① 跨场景可复用的默认身份映射层；② 场景级一次绑定、集中治理、改动传播；③ 全部执行面（单场景/令牌/预览/预检/图/集成/Suite/查询）同基础消费；④ 组合作为注册表的纯引用集，不引入明文/地址/环境/池等新维度。

**非目标**：不做运行期临时选组合（Runner 下拉形态已由 0 使用判死，每个运行入口不加第三层身份选择）；不恢复项目执行配置前端（11-18 决策，需求由组合 + 项目配置页签承接）；不引入新的凭证池选择规则（§3.4）；不做跨 scope 绑定（v1 硬同区，§5.3）。

## 2. 概念模型

### 2.1 三层职责

| 层 | 回答 | 复用性 |
|---|---|---|
| **账户组合**（新对象） | 这类场景，各服务默认用哪个身份条目 | 跨场景；个人 / 项目共享 |
| 运行方案 `serviceBindings` | 这个场景，某服务特例用谁 | 场景级覆盖 |
| 步骤直引（徽章面） | 这一步特例用谁 | 步骤级，罕见 |

```
账户组合(跨场景,个人/项目)      运行方案 serviceBindings(场景级覆盖)
        │ 基础默认                        │ 按服务覆盖
        └───────────┬────────────────────┘
                    ▼
   各执行面既有绑定合并(请求级/图级/单元级——面内现状不动)
                    ▼
             身份解析序(五层,§3.1)
                    ▼
   身份条目(注册表) → 账户池(credentialSource 链,§3.4)
        → 系统实例登录口 + authenticator → token → 完整执行
```

组合内容形状：`{ entries: [{service, alias}] }`——服务键 → **已登记**身份条目（`ServiceIdentity.alias_name`）。一条一服务；不存 envId（条目自带环境）、不存账户（条目引用账户）、不存地址与明文、不存凭证池。组合就是对注册表的引用集，完全遵守"新注册或选已注册"原则。

### 2.2 引用语义

- 场景**绑定**组合（不是拷贝进方案）；执行时活引用；
- 组合改动（换某服务的条目）→ 所有绑定场景**下次执行即生效**；
- 删除被引用组合 → 409 拒删（不静默悬空）；条目悬空 → 预检拦截（§6.3）；
- 与注册表"改密一处、装载它的条目全体生效"同一条原则，上提一层到身份映射维度。

## 3. 解析序与装配面

### 3.1 五层解析序

```
步骤直引(call.user / ${auth.X.token} 徽章,粒度最细天然优先)
  > 各执行面显式覆盖(单次请求 / 图级 / 单元级——面内现状保持不动)
  > 运行方案 serviceBindings
  > 账户组合条目(基础默认)
  > 服务键自身(effective_alias 既有回落)
```

组合与各面的关系恒为 `merged = {**组合条目, **该面既有合并结果}`——组合**永远垫底**，不重排任何面内覆盖序。

### 3.2 八装配面与垫底接法（实测，两轮评审核实）

| 执行面 | 绑定装配点（实测） | 面内覆盖序 | 垫底接法 |
|---|---|---|---|
| 单场景 JWT 运行 | dispatcher/prepare 直接消费请求 `serviceBindings`（前端按所选方案内联拼好；后端方案级仅进 `config_json` 溯源 `run_dispatcher.py:1650`） | 请求级（前端拼好） | prepare/dispatcher 后端权威垫底（不依赖前端拼全） |
| 单场景令牌运行 | `runs.py:143-146` `_apply_scheme_recipe` **整体覆写**（令牌自带即拒） | 服务端方案覆写 | **装载时合并**：覆写源 = `{**组合, **方案}`；不可在覆写前垫请求（会被冲掉） |
| 生效配置预览 | `routers/runs.py:387-395`（`/runs/preview`） | 请求级 > 方案 | 该合并处垫底（组合 < 方案 < 请求） |
| Suite 图 | `graph_dispatch.py:122-127`（方案级→单元级）、`:137-143`（图级→前两者） | 单元级 > 方案级 > 图级 | `resolve_graph_units` 取方案处垫底（图/单元覆盖自然在上） |
| 集成 | `integration_runner.py:463-498` `_load_exec_shape` → `resolve_for_run`；但 `_template_env`（:517）与 `_slot_bindings_of`（:568）**另读 `scheme_payload.serviceBindings` 原值** | 方案级 | `_load_exec_shape` 返回**规范化 scheme_payload**（合并终值写回该视图）——环境标签/订阅指纹/slot binding 三面自动同源 |
| Suite 直跑 | `suites.py:938-961` `_req_from_scheme`（**纯函数无 db 会话**，读**默认方案**） | 方案级 | **调用方垫底**：`run_suite`（:1043-1064）与预检（:1344）取默认方案后先合并再传入；函数签名不改 |
| 预检 | `routers/run_precheck.py:287`（直读方案绑定——独立装配面） | 方案级 | 该处垫底，与执行同基础 |
| 查询取数 | `query_context.py:86-88`（**定义级**绑定、无 schemeId） | 定义级 | schemeId 解析 + 垫底（§7.1） |

**统一实现取轻形态**：单点助手 `combo_base(db, scenario_row) -> dict`（读 `config.accountCombo` → 组合 `payload.entries` → 存活性校验），各面按上表接法一次合并；**不建大一统 resolver** 重排面内序。八面漂移风险由 §9 测试面的「装配面同基础断言」钉死。

### 3.3 池归属

**组合不引入任何新的池选择规则**。实测现状：场景在项目内 ≠ 自动用项目池；池由 `credentialSource` 显式链决定（缺省 = 执行人个人池；`"project"` 经 `can_use_project_credentials` 成员闸切场景所属项目池；两池互斥单源 `_pool_clause` `run_prepare.py:120-134`；定值点 `run_dispatcher.py:1281-1310`）。

组合 scope 管「**谁能治理这份映射**」，credentialSource 管「**从哪个池取账户**」——两维正交，互不干涉：

| 维度 | 决定什么 | 由谁定 |
|---|---|---|
| 组合 scope（user/project） | 映射的可见性、写权、可绑定场景（§5.3） | 绑定时的组合选择 |
| credentialSource（personal/project） | 执行时从哪个池解析账户 | 既有请求级字段 + 成员闸 |

「绑定即完整可执行」的承诺口径 = **绑定默认身份映射；以就绪报告确认当前池可执行**（账户可用性取决于执行人与 credentialSource，由就绪报告与预检显形兜底，§6.3/§6.6）。

## 4. 数据模型

### 4.1 新表 `account_combos`（Alembic 0067）

```python
id            PK
scope         'user' | 'project'      # ExecConfig 的 (scope, scope_id) 同款先例,无 FK
scope_id      int
name          ≤64, unique(scope, scope_id, name)
description   ≤2048
is_default    bool                    # partial unique:每 (scope, scope_id) 至多一条
              # 语义 = 「推荐默认」:新建场景时预选,不静默自动写入
payload       JSONB: {"entries": [{"service": str, "alias": str}]}
              # alias = ServiceIdentity.alias_name(必须已登记);一条一服务
revision      int, 初值 1              # 仅条目(entries)变化时 +1;
              # 改名/描述等元数据修改只动 updated_at+审计,不制造新身份映射版本
              # 溯源用:执行快照与订阅指纹记录 id+name+revision
updated_by_id int | None              # 项目组合多成员改动溯源
created_at / updated_at  (UtcDateTime,test_metadata_invariants 钉)
```

- **条目校验复用** `validate_binding_aliases`（`service_aliases.py:327-352`）：别名存在（`binding_alias_unknown`）∧ 与服务键同基础服务（`binding_alias_mismatch`）——不许借道改地址；组合自身新增码只留形状/重复类。
- 迁移纪律：增量升级门（快照链 `upgrade head` + 模型比对）+ 空库门 create_all 自动覆盖；部署前置 pg_dump（runbook 纪律，**排备份窗口**）。
- 存量 `exec_configs` **冻结**：3 行数据原样、CRUD 端点冻结、重跑回放照常（快照依赖，不动）。

### 4.2 场景侧引用键 `config.accountCombo`（platform sidecar，零迁移，**服务端托管**）

- 形态：`config.accountCombo: <combo_id>`；与 `service_scope` / `var_locks` 同族：**plate 边界剥离**（`plate_client.py:156` sidecar 清单加一键）。
- **服务端托管键**（消灭自动保存并发覆盖类）：
  - 唯一写通道 = `POST /api/scenarios/{sid}/account-combo`（§5.1）；整稿 PUT **恒剥** incoming 的 `accountCombo` 并**保留存量值**（先例：`param_slots` 的 `not in model_fields_set` 保留分支 + `users` 明文闸"不许新增、保留存量"）；
  - 编排器前端 draft 不携带该键（组合选择单独 ref 管理，走绑定端点）——2.5s 防抖全量 PUT（`CaseComposer.vue:361-389`）无论何时触发都抹不掉绑定；
  - 由此**不引入乐观锁 / expectedUpdateTime**（场景 PUT 全仓 last-write-wins 为既有现状，不为此扩栈）。

### 4.3 生命周期：复制 / 导出 / 导入

**`copy_scenario()` 恒剥**（先例 = `users`「副本=新建，恒剥」`scenario_store.py:716-725`）——七个调用方路径一律不带组合引用，副本重新绑定：

## 5. API 面（新 router `account_combos.py`）

### 5.1 端点

| 端点 | 门 | 说明 |
|---|---|---|
| `GET /api/account-combos[?projectId]` | 个人 = 本人；项目 = 成员任一角色 | 列表按 scope 分组返回（含引用计数，供编辑/删除前差异确认） |
| `POST`（个人） | 任意登录用户 | |
| `POST`（项目） | 项目可写角色（WRITER_ROLES）∧ **目标为普通项目**（公共项目 → 422：不把环境与凭证引用发布成公共模板） | |
| `PATCH /{id}` | 同上写门 | 改名/描述/条目；**条目逐条过 `validate_binding_aliases`**（别名未登记/异基础服务 → 422 复用既有码族；形状/重复服务 → 422 `account_combo_entry_invalid`）；**仅条目变化 `revision` +1**；记 `updated_by_id` |
| `POST /{id}/set-default` | 写门 | 换默认（旧默认自动摘除） |
| `DELETE /{id}` | 写门 | **被引用时 409 `account_combo_in_use` + 引用场景清单**；不解绑不给删；in-use 复核与删除**同事务** |
| `GET /api/scenarios/{sid}/account-combo` | 场景读闸（表 B read） | **读取通道**：返回当前绑定（comboId + 名称/revision/条目摘要）；编排器重载恢复显示 |
| `POST /api/scenarios/{sid}/account-combo` | 场景写闸（表 B write）∧ 组合可读 ∧ **同区**（§5.3） | **v1 唯一应用入口 = 编排器**：`{comboId: int \| null}`；null = 解绑；**避免整稿 PUT** |

### 5.2 错误码（全进契约快照：AST 提取 → `error-codes.json` → 前端 `errorCodes.ts`）

| 码 | 状态 | 面 |
|---|---|---|
| `account_combo_not_found` | **404**（资源端点 GET/PATCH/DELETE `/{id}`、set-default）/ **422**（场景侧绑定闸：引用了不存在或不可读的组合）——同码双态，face 决定 status | 组合资源 / 场景绑定 |
| `account_combo_entry_invalid` | 422 | PATCH 条目形状/重复服务 |
| `account_combo_scope_mismatch` | 422 | 跨区绑定（§5.3） |
| `account_combo_in_use` | 409 | 删除被引用组合 |
| `identity_combo_missing` | 409 | 预检与执行侧：组合缺失/引用服务的条目悬空（§6.3） |
| `query_identity_ambiguous` | 422 | 查询侧多身份无法唯一判定（§7.3） |

**运行期分类沿用既有精度**（`run_precheck.py:57-58`/`:452-481` 既有分类不动）：组合不存在/条目悬空 → `identity_combo_missing`；**条目在、当前池无账户 → 沿用 `account_missing`**；多候选无唯一命中 → 沿用 `account_ambiguous`；异基础服务 → 保存期 `binding_alias_mismatch`。

### 5.3 范围矩阵（v1 硬同区规则）

| 组合范围 | 可绑定场景 | 读 | 写 | 执行凭证 |
|---|---|---|---|---|
| 个人组合 | **仅本人私有场景** | 属主 | 属主 | 按 credentialSource 链解析 |
| 项目组合 | **仅同一普通项目场景**（跨项目即使双成员也拒） | 项目成员任一角色 | 项目 admin/member（WRITER_ROLES）；平台 Admin 不旁路（按成员关系判，同 `zone.py` 既有语义） | 按 credentialSource 链解析 |
| 公共场景 | 不绑定（发布恒剥，§4.3） | — | — | 无组合依赖 |
| 公共项目 | 不创建组合 | — | — | — |

收益：个人对象不进项目资产——项目管理员可维护一切影响项目场景的映射；成员退出/属主删号不留悬空依赖（个人组合只挂本人私有场景，用户删除按既有 cat3 处置连坐；项目组合属项目资产，成员移除无影响）——**零跨资产残留，无需新增清理钩子**。跨 scope 松绑留待后续（前提：成员只读视图/退出处置/接管/删除影响/快照记属主五条规则成文）。

### 5.4 审计与项目治理

- 审计事件：创建 / 修改 / 设默认 / 删除 / 绑定 / 解绑，入既有审计流；

## 6. 执行链

### 6.1 垫底合并

各装配面按 §3.2 表「垫底接法」逐面接入（四点实现约束：令牌面**装载时合并**防覆写冲掉；集成面经 `_load_exec_shape` **规范化 scheme_payload** 收口三面同源；Suite 直跑**调用方**垫底（纯函数不改签名）；**预检面**补入装配面清单）。步骤直引不受影响（粒度更细，天然优先）。

### 6.2 环境

组合条目 = 身份条目，自带环境标签 → `resolve_execution_tag` 原链照走（身份标签 > 项目默认 > 平台默认）；集成面吃规范化 payload，环境标签解析自动含组合身份。

### 6.3 校验分层 + fail-closed

| 层 | 校验范围 |
|---|---|
| **保存期**（PATCH 组合） | 全量条目：存在、形状、服务不重复、同基础服务（§5.1） |
| **就绪页/管理页** | 全量条目展示在指定池的命中状态（§6.6） |
| **场景执行/预检** | **只校验本场景实际引用的服务**的组合条目——未引用服务的悬空条目不阻断执行 |

- 引用服务的组合条目悬空（组合被删——不应发生，删除有 in-use 闸，悬空仅来自竞态；或别名被注销）→ **409 `identity_combo_missing`（携带 comboId / service / 缺失 alias），绝不以裸键继续执行**；诊断面可展示回退解析结果，仅供修复定位，不用于执行；
- 池无账户 / 多候选沿用既有 `account_missing` / `account_ambiguous`（§5.2）；
- 修复组合或重新绑定后自动恢复（同 `missing_credential` 族语义），并**显式触发集成实例复活钩子**（既有暂停/复活模式）。

### 6.4 执行快照

`config_json.serviceBindings` 存**合并终值**；溯源键 `accountComboId + accountComboName + accountComboRevision`；重跑按既有原则吃快照终值（不随组合后续修改漂移）。

### 6.5 订阅指纹（集成知情同意）

`consent_fingerprint` 投影（`integration_runner.py:445-458`，现含 alias_creds/slot_bindings）**显式加入 `accountComboId + accountComboRevision`**——组合绑定或条目变化 → 指纹变 → 非 owner 订阅者重新确认（知情同意覆盖"身份映射来源变了"本身，而不仅是终值巧合相同）。

### 6.6 就绪诊断 / 拨测

组合的逐服务装载、地址矩阵、Ping All 复用既有解析器（`getSlotStatus` / 部署表 / Ping All 范式）；共享（项目）组合的就绪结论**标注执行池上下文**（"以当前用户/个人池"或"以项目池试解析"，可切换）；逐服务显示：服务 → 组合条目 alias → 身份条目环境 → 池命中（credentialSource 决定）→ 账户 ✓/✗，池不匹配标黄。

## 7. 查询链（与执行同基础）

1. **方案感知**：rows 上下文增 `schemeId` 参数（前端传当前生效方案；缺省回落默认方案——与执行面 `resolve_for_run` 同款回落）；`resolve_query_context` 的绑定基础从「定义级」改为「schemeId 解析 + 组合垫底」（查询视角 = 执行视角的既有裁定）。
2. **步骤身份扫描补齐**：现前端只扫 headers `${auth.*}`（`CaseComposerCanvas.vue:1365-1371` `headerAuthTagOf`），不覆盖 `call.user` 直引；后端已有含 `call.user` 的扫描器 `auth_ref_scan.step_auth_refs`（`:39-41`）——查询链接线复用，前端 `headerAuthTagOf` 同步补 `call.user` 分支。
3. **多身份不猜测**：同一步存在多个直接身份且无法唯一判定 → 422 `query_identity_ambiguous`，不取第一个。
4. **池通道与缓存隔离**：查询凭证加载器 `_loader`（`query_views.py:40`）增 `cred_project_id` 通道（`_resolve_identities` 既有参数，现状查询链恒走个人池）；查询 L1 缓存键 `(name, ref, (owner_id, query_alias))`（`query_view_runner.py:390-395`）与单飞锁键增凭证池维度——个人池/项目池不串缓存。

## 8. 前端

### 8.1 编排器（场景接入 UX）

**配置页签「凭证与调用身份」区**：

```
使用组合: [测试组合 · 项目 ▾]  [存为组合] [解除]
逐服务:   fin  → fin-qa1(组合)     → 账户 ✓
          jira → jira-ops2(组合)   → 账户 ✓
          logi → logi-w1(方案覆盖) → 账户 ✓     ← 覆盖/直引处带徽章标注来源
```

| 交互 | 定义 |
|---|---|
| 未使用组合 | 现状不变（步骤直引 / 裸键裸跑、预检拦）——组合可选增强，不强制 |
| 新建场景 | 项目默认组合**预选**（不自动写）；预选态与已绑定态**视觉区分**（「默认预选，尚未绑定」）；保存场景不自动落绑定 |
| 存为组合 | **只快照方案绑定层**；步骤直引的服务**单独列出**（「身份来自步骤级直引，不自动收进组合」，可显式手补一条）；不自动覆盖、不自动收敛步骤身份；**scope 显式选择**（个人/项目），项目场景默认项目 scope |
| 切换/解除 | 一步改引用（走绑定端点），不动方案绑定与步骤；**解除前提示哪些服务仍由方案绑定或步骤直引覆盖**（同服务有覆盖时解除表面无变化） |
| 改动传播 | 组合换条目 → 绑定场景下次执行即生效；**保存前差异确认**（引用场景数 + 变更差异 + 有引用时二次确认）；悬空由预检与徽章显形 |
| 导出/导入 | 引用不随包迁移；导出报告与导入预检列**需重新绑定的服务清单** |

步骤卡声明式徽章 + 就地"新建即注册"保留立项（定位：步骤级覆盖 + 注册缺口就地补，另批实施）。

### 8.2 管理页（壳保留、语义旋转，v1 收敛四区）

`ExecConfigsView` 壳改绑组合端点；**「生效预览」「应用到场景」不在无场景上下文时保留空壳**（应用入口 v1 只在编排器）：

| 区 | 内容 |
|---|---|
| ① 组合列表 | scope 分组（个人 / 我所在的项目）、默认标记、**引用计数** |
| ② 组合编辑 | 服务 → 身份条目、来源、**池命中状态**（v6 已选列表 + 搜索加入的形式不动） |
| ③ 就绪度 | **明确执行池上下文**的装载诊断 + 地址矩阵 + **Ping All 留家**（"以当前用户/个人池"或"以项目池试解析"，可切换） |
| ④ 引用场景 | 被哪些场景使用、跳转场景——只读清单，不做批量应用 |

### 8.3 退场面

- Runner 页执行配置下拉：**移除**；
- 导航「配置」→「**账户组合**」（路由新 `/account-combos`，旧 `/exec-configs` 重定向，书签兼容同 `/profile/config` 先例）；

## 11. 已定决策（演化收敛记录，防回退）

完整论证与被推翻的中间结论（14 条决策轨迹、两轮评审逐条处置）见 `02-account-combo-design.md` §2/§13。定稿要点：

1. **引用语义**（非拷贝）——拷贝语义组合一拷即逝，场景不"使用"组合；
2. **净路径新表** `account_combos`，旧 `exec_configs` 冻结——不混淆两代语义，零数据迁移；
3. **sidecar 键 + 服务端托管**——零迁移且消灭自动保存并发覆盖类（不用乐观锁）；
4. **组合永远垫底**——五装配面各有覆盖层且合并序不一（图级实为最低层），不建大一统 resolver 重排面内序；
5. **组合零池规则**——scope 管治理、credentialSource 管取账户，两维正交；
6. **v1 硬同区绑定**——个人对象不进项目资产；跨 scope 松绑留待后续五条规则成文；
7. **fail-closed + 校验分层**——执行只校验引用服务；错误码沿用既有分类精度；
8. **存为组合不收敛直引**——只快照方案层，直引显式列出；
9. **管理页壳保留语义旋转**——v1 四区，应用入口只在编排器；
10. **订阅指纹含 comboId+revision**——身份映射来源变化触发知情重新确认。
