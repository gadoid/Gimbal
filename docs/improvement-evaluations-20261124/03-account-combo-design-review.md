# 账户组合设计评审

> 评审日期：2026-11-25
> 被评审文档：`02-account-combo-design.md`（2026-11-25 设计稿）
> 代码基线：`origin/fix/core-wrapup@876bd0e7`
> 性质：设计评审与开工前契约收口

## 1. 总体结论

**整体方向没问题，可以作为配置页重构的主线。**

账户组合填补了“全局身份注册表”和“场景运行方案”之间真实的复用层缺口；采用引用语义、新建组合表、场景 sidecar 引用、旧执行配置冻结，都是合理的净路径。

当前建议是：

- **批准设计方向**；
- **不批准设计稿直接进入执行链消费批次**；
- 先补齐统一解析、范围与凭证池、跨区生命周期、查询上下文四项契约，再进入批 2。

## 2. 设计中已经成立的部分

1. **对象定位准确**
   - 账户组合回答“这类场景的各服务默认使用哪个身份条目”。
   - 运行方案回答“本场景某服务的特例覆盖”。
   - 步骤直引回答“本步骤的特例身份”。

2. **引用语义正确**
   - 组合修改后，引用场景在下一次执行时生效。
   - 不把组合拷贝进方案，避免形成一次性快照。

3. **净路径合理**
   - 新表 `account_combos`，不混淆旧 `exec_configs` 的语义。
   - 旧表、旧端点和历史回放冻结保留。
   - 场景引用放平台 sidecar，不修改 Plate 的 M2 模型。

4. **快照方向正确**
   - 执行快照保存合并后的终值，保证重跑不随组合后续修改漂移。
   - 需要补充组合版本或 revision，增强溯源能力。

## 3. 开工前必须修订的问题

### 3.1 建立统一绑定解析器

设计稿假设在 `run_prepare/dispatcher` 合并方案绑定即可，但当前实际存在多个装配点：

| 执行面 | 当前绑定装配位置 |
|---|---|
| 单场景运行 | `routers/runs.py:392`，方案绑定与请求覆盖合并 |
| Suite 图 | `services/graph_dispatch.py:122`、`:137`，图级、单元级、方案级合并 |
| 集成 | `services/integration_runner.py:479`，直接读取方案绑定 |
| Suite 直跑 | `routers/suites.py:955`，从方案构造 `RunRequest` |
| 查询取数 | `services/query_context.py:87`，读取定义级绑定且无 `schemeId` |

如果只在 dispatcher 接入组合，Suite、集成和查询会很快漂移。

**建议**：先建立单点解析器，例如：

```text
resolve_scenario_bindings(
    scenario_row,
    scheme_payload,
    request_or_graph_overrides
)
```

完整优先级应明确为：

```text
步骤直引
  > 单次请求 / 图级 / 单元级显式覆盖
  > 运行方案 serviceBindings
  > 账户组合
  > 服务键自身
```

设计稿原优先级“步骤直引 > 方案 > 组合”漏掉了当前已经存在的请求级和图级覆盖层。

### 3.2 明确组合范围与凭证池归属

身份条目 `ServiceIdentity` 是全局引用，不包含凭证归属；实际账户来自个人池或项目池。当前执行通过独立的 `cred_project_id` 选择池，见 `run_prepare.py:729`；查询凭证加载器只接收 `owner_id`，见 `query_views.py:40`。

因此组合只保存 `{service, alias}` 时，不能直接承诺“绑定一次即完整可执行”。

建议明确以下规则：

- 个人组合只能用于私有场景，默认个人凭证池。
- 项目组合只能用于同一普通项目场景，默认项目凭证池。
- 公共场景不保留组合引用。
- 如允许显式切换个人/项目池，必须在就绪报告和执行快照中显示 `credentialSource`。

否则会出现“组合可见、身份条目可见，但当前执行池没有账户”的状态。

### 3.3 补齐跨区复制与发布规则

设计稿处理了导出和导入，但当前 `copy_scenario()` 会深拷贝整个 payload，目前只剥离 `users`，见 `scenario_store.py:715-725`。

以下路径都会直接带走 `config.accountCombo`：

- 复制到我的；
- 发布到公共库；
- Suite fork；
- 项目晋升；
- 其他基于 `copy_scenario()` 的副本路径。

建议规则：

| 路径 | 建议行为 |
|---|---|
| 项目场景 → 我的私有副本 | 剥离项目组合，要求重新选择个人组合 |
| 私有场景 → 发布公共副本 | 剥离组合，公共场景不依赖个人或项目凭证 |
| 私有场景 → 加入或晋升项目 | 个人组合不自动跨区，提示改绑项目组合 |
| Suite fork | 与场景复制同规则 |
| 导出、导入 | 按现稿剥离，并在预检报告明确说明 |

### 3.4 查询链增加方案和步骤身份上下文

设计稿要求查询与执行同解析，但当前查询上下文只有 `scenarioId + stepIndex`，无法知道用户选的是哪个运行方案。方案绑定不同时，查询可能拿到错误身份。

前端查询身份目前只扫描 headers 中的 `${auth.*}`，见 `CaseComposerCanvas.vue:1365`，没有覆盖 `call.user` 直引。

建议：

- rows 上下文增加 `schemeId`；
- 查询身份解析复用后端步骤引用扫描，优先 `call.user`，再处理模板直引；
- 同一步存在多个直接身份且无法唯一确定时，报 `query_identity_ambiguous`，不猜第一个；
- 查询缓存键加入凭证池来源。当前键为 `(name, ref, owner_id + alias)`，见 `query_view_runner.py:390`；支持项目池后必须加入 `cred_project_id`，避免个人池和项目池串缓存。

### 3.5 缺失组合必须 fail-closed

设计稿提出“组合被删或条目悬空时回退裸键”，这有误用同账号的风险。

建议：

- 明确报 `identity_combo_missing`；
- 错误携带 `comboId`、`service`、缺失 alias；
- 不把服务键当成另一个身份继续执行；
- 修复组合或重新绑定后再恢复。

组合条目保存时还必须复用同基础服务校验。现有 `validate_binding_aliases()` 已实现“别名存在且与服务同基础服务”，见 `service_aliases.py:327`；组合不能只校验别名是否存在。

### 3.6 处理绑定与删除的并发

`POST /scenarios/{sid}/account-combo` 避免整稿 PUT 是对的，但场景仍有自动保存。可能发生：

1. 组合绑定请求成功；
2. 较旧的整稿自动保存成功；
3. `accountCombo` 被旧 payload 覆盖。

建议使用行锁或 `expectedUpdateTime`，冲突返回 `scenario_update_conflict`。删除组合的 in-use 检查也应在事务内复核，避免检查后刚好被新场景绑定。

### 3.7 补齐版本、审计和项目治理

组合修改会影响所有引用场景，建议最低增加：

- `revision` 或 payload hash；
- `updated_by_id`、`updated_by_name`；
- 创建、修改、设默认、删除、绑定、解绑审计；
- 编辑或删除前展示引用场景数和清单；
- 执行快照记录 `accountComboId + revision + name`，不只记录 ID。

项目详情资源计数和删除内容闸也需要加入 `account_combos`。当前项目删除只检查场景、套件、集成和报表定义，见 `projects.py:473`。

## 4. 设计稿中应直接修正的两处

### 4.1 错误码状态不一致

设计稿 §4.2 写保存闸 `account_combo_not_found → 422`，§5 又写 `404`。

建议：

- 组合资源不存在：404；
- 场景引用了不存在或不可读的组合：422。

### 4.2 “存为组合”不能收敛步骤直引

设计稿提出“方案绑定 ∪ 直引收敛”快照成组合。一个服务可能有多个步骤直引不同身份，收敛会丢信息。

建议：

- 只快照场景级默认；
- 存在步骤直引时展示冲突；
- 不自动覆盖步骤身份。

## 6. 验收补充

除设计稿已有测试外，至少补充：

- 单次请求覆盖、方案覆盖、组合默认、步骤直引的完整优先级矩阵；
- Suite 直跑、Suite 图、集成、查询使用同一解析结果；
- 个人组合、项目组合、公共场景的范围矩阵；
- 项目凭证池与个人凭证池的查询缓存隔离；
- 非默认方案查询使用正确身份；
- `call.user` 与多个步骤直引的查询行为；
- 复制、发布、Suite fork、项目晋升不泄漏跨区组合引用；
- 别名与服务不同基础服务时保存失败；
- 组合缺失时 fail-closed，不回退裸键；
- 自动保存与组合绑定的并发覆盖测试；
- 组合 revision、审计和执行快照溯源；
- 项目删除和资源计数包含账户组合。

## 7. 最终建议

**方向批准，契约修订后再进入执行链开发。**

统一解析、凭证池归属、跨区复制和查询上下文是必须先补的四项。它们不改变账户组合的产品方向，但决定这个对象能否在单场景、Suite、集成和查询之间保持一致。
