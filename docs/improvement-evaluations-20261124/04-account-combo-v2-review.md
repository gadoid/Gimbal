## 3. 批 2 前必须钉死的实现约束

### 3.1 令牌执行不能被方案覆写冲掉组合

`_apply_scheme_recipe()` 会整体覆盖 `body.service_bindings`，见 `routers/runs.py:143-146`。

因此不能在它“之前”把组合垫进请求，否则组合会被方案覆写冲掉。

正确顺序应为：

```text
方案装载时合并：combo + scheme
再整体覆写令牌请求
```

或覆写后再以方案为覆盖层合并组合。

### 3.2 集成的环境与订阅指纹必须消费合并后的绑定

当前 `_template_env()` 和 `_slot_bindings_of()` 读取的是 `scheme_payload.serviceBindings`，不是 `_load_exec_shape()` 返回的 `bindings`，见：

- `services/integration_runner.py:501-519`；
- `services/integration_runner.py:552-568`；
- `services/integration_runner.py:609-626`。

如果组合只存在于返回的 `bindings`，可能出现：

- 执行使用组合身份；
- 环境仍按原方案身份解析；
- 订阅指纹没有反映组合实际账户。

建议二选一：

- 返回规范化后的 scheme payload，将合并后的 `serviceBindings` 放回该视图；
- 或让环境、指纹、slot binding 函数显式接收合并后的 bindings。

订阅指纹还应显式加入：

```text
accountComboId + accountComboRevision
```

组合绑定或条目变化必须触发非 owner 订阅者重新确认。

### 3.3 Suite 直跑要在调用方合并

`_req_from_scheme()` 是纯函数，没有数据库会话，见 `routers/suites.py:938`。

不能把 `combo_base()` 直接塞进该函数。应在调用方先读取组合并合并，或修改函数签名显式传入合并后的方案绑定。

### 3.4 补齐预检面和当前绑定读取接口

`/run/precheck` 是独立装配面，当前直接读取方案绑定，见 `routers/run_precheck.py:287`，必须同步垫底。

服务端托管键还需要读取通道：

```text
GET /api/scenarios/{sid}/account-combo
```

否则编排器重新加载后无法恢复显示当前绑定的组合。

### 3.5 运行时校验范围与错误分类

建议区分：

- **组合保存**：校验全部条目存在、形状合法、服务不重复、同基础服务。
- **组合就绪页**：展示全部条目在指定池的命中状态。
- **场景执行**：只强制校验本场景实际引用服务的组合条目。

否则组合中一个未使用服务的别名失效，也会阻断场景执行。

错误码建议保持精度：

- 组合不存在、组合别名悬空：`identity_combo_missing`；
- 身份存在但当前池无账户：沿用 `account_missing`；
- 账户歧义：沿用 `account_ambiguous`；
- 别名与服务不同基础服务：保存期沿用 `binding_alias_mismatch`。

组合修复或重新绑定后，显式触发集成实例复活钩子。

### 3.6 revision 语义

`revision` 建议只在组合条目发生变化时递增。名称、描述等元数据修改更新 `updated_at` 和审计即可，不应制造一次新的身份映射版本。

## 4. 交互审查

### 4.1 整体清晰的部分

- 编排器选择、绑定、解除、存为组合的主流程清楚；
- 组合、方案、步骤直引的来源徽章方向正确；
- 新建场景默认组合“预选但不自动写”正确；
- 管理页保留外壳、退役无意义控件，改造幅度可控；
- 导出导入不携带组合引用，符合环境隔离原则；
- 修改组合后引用场景下次执行生效，符合集中治理目标。

### 4.2 需要补齐的交互定义

| 交互点 | 当前问题 | 建议 |
|---|---|---|
| “一键绑定即完整可执行” | 组合不含凭证池，账户是否可用取决于执行人和 `credentialSource` | 改为“绑定默认身份映射；以就绪报告确认当前池可执行” |
| 管理页“应用到场景” | v1 没有场景选择器，也没有说明从哪个入口选择目标场景 | v1 只在编排器应用；管理页保留引用清单和跳转 |
| “存为组合” | 个人/项目归属如何选择没有明确默认 | 增加明确 scope 选择；项目场景默认项目 scope |
| 就绪度、Ping All | 共享组合没有唯一“就绪”结论，结果取决于当前用户和凭证池 | 标注“以当前用户/个人池”或“以项目池试解析”，必要时允许切换 |
| 修改传播 | 会影响所有引用场景，但缺少保存前差异确认 | 展示引用数量、变更差异；有引用时二次确认 |
| 解除组合 | 同服务存在方案覆盖时，解除后表面可能无变化 | 解除前提示哪些服务仍由方案或步骤直引覆盖 |
| 默认预选 | 预选和已绑定容易混淆 | 显示“默认预选，尚未绑定”，保存场景不自动落绑定 |
| 导出、导入 | 组合引用不随包迁移 | 导出报告和导入预检明确列出需重新绑定的服务 |

### 4.3 v1 管理页建议

v1 建议收敛为四个区域：

1. **组合列表**：个人/项目分组、默认标记、引用数量；
2. **组合编辑**：服务与身份条目、来源、池命中状态；
3. **就绪度**：明确执行池上下文的装载诊断和 Ping All；
4. **引用场景**：查看被哪些场景使用，跳转场景，不直接执行批量应用。

“生效预览”和“应用到场景”不要在没有场景上下文时保留空壳。

## 5. 权限管理边界审查

### 5.1 已清晰的部分

- 个人组合：本人管理；
- 项目组合：项目成员可读，项目管理员/成员可写，项目用户只读；
- 场景绑定：场景写闸 + 组合可读；
- 组合不保存明文，不直接授予凭证读取权；
- 实际凭证仍由执行人个人池或项目池决定；
- 公共场景发布时剥离组合；
- 复制、fork、晋升恒剥组合；
- 服务端托管键防止前端越权改写；
- 审计、revision、项目删除闸均已覆盖。

现有项目角色语义可以直接复用：

- `WRITER_ROLES = admin + member`；
- 项目 `user` 角色只读 + 执行；
- 项目凭证只要当前项目成员即可使用，平台 Admin 不旁路，见 `services/zone.py:55-63`；
- 场景写权为属主或项目 contributor，见表 B `scenario.write`。

### 5.2 关键不清晰点：个人组合能否绑定项目场景

v2 默认允许，但这会形成治理断层：

- 项目场景依赖成员个人对象；
- 项目管理员无法维护该组合；
- 其他项目成员可能看不到组合映射，却受其修改影响；
- 所有者退出项目后，项目资产仍残留个人依赖。

**建议 v1 采用硬范围规则：**

| 组合范围 | 可绑定场景 | 读权限 | 写权限 | 执行凭证 |
|---|---|---|---|---|
| 个人组合 | 仅本人私有场景 | 属主 | 属主 | 仍按执行链个人池解析 |
| 项目组合 | 仅同一普通项目场景 | 项目成员 | 项目 admin/member | 按 `credentialSource` 解析个人池或项目池 |
| 公共场景 | 不绑定组合 | 无 | 无 | 无组合依赖 |
| 公共项目 | 不创建组合 | 无 | 无 | 无 |

组合 scope 管的是“谁能治理这份映射”，`credentialSource` 管的是“从哪个池取账户”，两者应保持独立。收紧组合 scope 不与现有凭证池架构冲突。

### 5.3 如果坚持允许个人组合进入项目场景

则必须同时补齐：

- 项目成员可只读查看组合映射；
- 组合所有者退出项目后的处置规则；
- 项目管理员如何接管或解除该依赖；
- 组合删除、停用对项目场景的影响；
- 项目执行快照和审计明确记录组合属主。

在这些规则未定义前，不建议开放跨 scope 绑定。

### 5.4 其他权限补充

- 项目组合不得跨项目绑定，即使调用者同时是两个项目成员。
- 平台 Admin 不旁路项目组合权限，仍按项目成员关系判断。
- 组合可读不等于凭证可读或可使用；执行仍过项目成员闸和账户池解析。
- 集成订阅指纹必须包含组合 ID/revision；组合绑定变化触发重新确认。
- 用户删除、项目成员移除时，要明确组合引用和集成实例的清理/暂停行为。
- 项目组合创建应拒绝公共项目，避免把环境与凭证引用发布成公共模板。

## 6. 验收补充

除 v2 已列测试外，建议增加：

- 令牌执行合并顺序：组合不会被方案覆写冲掉；
- 集成环境、指纹、slot binding 都使用合并后的绑定；
- Suite 直跑调用方正确合并组合；
- `/run/precheck` 与执行结果一致；
- 当前组合绑定读取接口在刷新、跳转后正确恢复；
- 组合中未使用服务失效不阻断场景执行；
- 当前池无账户与组合别名悬空使用不同错误码；
- 组合修复后集成实例按预期复活；
- 元数据修改不增加 revision，条目修改增加 revision；
- 个人/项目/公共范围矩阵；
- 项目组合跨项目绑定被拒；
- 公共项目不能创建组合；
- 平台 Admin 非项目成员不能管理项目组合；
- 共享组合就绪度和 Ping All 明确展示执行池上下文；
- 组合修改有引用时展示差异并确认；
- 解除组合时正确提示方案覆盖和步骤直引仍生效。
