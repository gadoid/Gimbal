## 1. 两件事与字段三面(用户定纲 2026-09-11)

**事 1 数据集改造**:只取模板,基于模板填充(正常数据变体),支持直接向被测系统查询选择值(单变量面板取数,复用注册查询视图)。

**事 2 测试数据字段绑定协议** — 字段三面,全部落在断言管理条目上:

| 面 | 载体 | 说明 |
|---|---|---|
| 引用 | 编排器标记 → anchor(jsonpath + varName) | 哪个字段、被哪个变量喂 |
| 值映射 | `injection: [{varName, value}]`(**住条目里,不住数据集**) | 偏离值 |
| 策略注入 | `asserts: [{step, target, operator, expected, mode}]` | 值变动的断言(其他策略留协议位) |

裁定记录(2026-09-11 用户拍板):

- **数据集 = 正常业务过程数据;断言管理 = 对正常过程的偏离注入 — 异常不进数据集**
- v1 只做断言策略,其他策略种类留协议位
- 负向用例 v1 直接失败(不建终止机制),后续改造
- 模板即地址:独立控制 = 拆模板(改场景);未模板化字段对数据集不可见(与直填退场一致)
- 注册表 = 场景级资产;覆写 + 追加两形态都要;两组件低耦合,唯一汇合点 = 运行时(§5)
- CSV v1 只导值

## 2. 场景纯化

- **exp_* 期望变量退役**:T2 期望提升链(编排器断言卡 expected → `${var.exp_*}`)整体退场;场景断言 expected 回归字面量(流程不变量)
- **合法保留**:引用输入变量的一致性断言(expected = `${var.x}`,如「回显金额 == 提交金额」)— 属过程描述,不在退役之列
- 场景 strategy 仍是**断言形状唯一事实源**;注册表条目只登记引用与偏离,不复制场景断言定义(§3)

## 3. 断言管理注册表(场景级)

**家**:场景文档平台侧新节 `assertion_registry`(与 orchestration 同级,**不入 gimbal definition/config — 引擎不感知**)。编辑入口 = 编排器配置区「断言管理」节 + 独立编辑视图(§7)。

条目形状(自含:偏离值 + 期望配对):

```jsonc
{
  "id": "inj-1",
  "name": "金额为负",
  "anchor": { "stepIndex": 0, "source": "body", "jsonpath": "$.amount", "varName": "amount" },
  "injection": [{ "varName": "amount", "value": "-1" }],
  "asserts": [
    { "stepIndex": 0, "target": "$.response_body.code", "operator": "eq", "expected": "400", "mode": "override" }
  ]
}
```

- **anchor = 溯源面**(编排标记自动带来;编辑器联动/展示用,执行不依赖)
- **injection = 值偏离面**(数组,v1 长度通常 1;多字段注入留位)— 物化 = 基线 vars 覆写
- **asserts = 期望偏离面**(数组,一个故障多观测面):`mode: override` 覆写场景既有断言(匹配键 = stepIndex + target,同 target 多条加 operator)/ `append` 追加场景没有的断言
- **负向必须 override**(场景 `code==0` 不变则两条断言同场必失败)
- 条目结构不问值是否"异常" — 它是「值偏离 + 期望偏离」配对;正常边界值配不同期望同样走条目(正常/异常是使用语义,非结构约束)
- **悬空检测**:stepIndex 越界 / override 匹配不到既有断言 / injection.varName ∉ config.vars → 死条目软提示(死键同款)+ 跳编排器链接。步骤/变量引用 = 索引/名,场景编辑移位由载入检测兜底(v1 接受)
- 手工建条目合法(无 anchor 仍可用,联动建议缺席)

## 4. jsonpath 全字段解析能力(2026-09-11 用户提出,已验证可行)

现有三层机器:

1. **契约层**:declarations 自带 `path` = 权威 jsonpath(深路径 / 数组 `$[N]`,D1-D12 已铺)— 标记时优先取契约路径
2. **实例层**:dataset-segments `scanValue` 深扫 body/headers 建路径(数组 `[i]` / 深路径点连)— 现只报告含 `${var}` 的位置
3. **响应层**:plate 契约 `assertable`(仅响应侧,io_spec `DeclarationEntry`,§6 B3「断言面标记」)+ 前端 `assertablePaths()` 投影 — 断言面候选的契约钩子已在

**新增**:`fieldPathsOf(step)`(utils)— 全叶子路径报告,每叶子 `{source, path, varName?}`;模板引用为叶子属性;未声明字段兜底(有路径,无 description/ui_kind)。

编排器标记:

- **请求侧**:字段卡「加入断言管理」→ 自动带 jsonpath + varName(其模板引用)作 anchor
- **响应侧**:断言面候选 = `assertable` 契约(B3 既有语义)
- FieldActionMenu.vue 为用户 WIP,实施时协调标记入口落点

## 5. 两组件语义分工与运行时汇合(2026-09-11 用户裁定)

| 组件 | 语义 | 感知 |
|---|---|---|
| 数据集 | 同一业务过程的**正常数据变体**(行 = 纯 var-dict,全部应过场景默认断言) | 不知道断言管理存在 |
| 断言管理 | **偏离注入**(条目自含 偏离值 + 期望,§3) | 不知道数据集存在 |
| ~~绑定配置 assertion_bindings~~ | **退场**(v2 修订二的方案作废) | — |

- **唯一汇合点 = 运行时**:RunDialog 选数据集(正常组,既有)+ 多选注入条目(异常组,新);选择可入既有运行方案(runSchemes)机制
- 两族 case 同场执行:正常行 N 条 + 注入条目 M 条
- **注入条目跑在基线上**(config.vars = 典型正常单,注入扰动它);注入 × 数据集矩阵组合 = v2 协议位
- 行保持纯 var-dict 零保留键;现有数据集 / CSV / TSV 零影响(CSV 只导值不变)

## 7. 断言管理编辑器

- 条目列表(名称 / 锚定字段徽标 / 偏离值摘要 / 期望数 / 死条目标灰)
- 条目详情:anchor(跳编排器)+ injection 值编辑 + asserts 列表(target/operator/expected/mode)

## 8. 物化链(平台层,引擎零改动)

两族 case 同一物化函数族:

- **正常行**:`materialize(行)` = 深拷贝场景 → vars 合并(行值)— 既有链不变
- **注入条目**:`materialize(条目)` = 深拷贝场景 → 基线 vars + injection 覆写(`vars[varName] = value`)→ asserts patch(override 改 expected / append 加断言)

- 负向用例:下游步骤直接失败(v1 裁定)
- 旧 exp_* 物化路径迁移期保留(§9);执行 / 导出同源(黄金等价测试继续锁死)

## 9. 存量迁移(读兼容 + 惰性一键迁移)

- **读兼容**:场景含 `${var.exp_*}` 形态 → 数据集照旧可跑(旧物化路径保留)
- **一键迁移**(手动触发;exp_* 键 = 「该行偏离正常契约」的既有标记,按它切分):
  1. 断言 expected `${var.exp_*}` → 字面量(config.vars[exp_*] 基线值)
  2. 数据集中**带 exp_* 键的行 → 整行转注入条目**(injection = 该行的值偏离键值对;asserts = exp_* 键的期望配对,override),并**从数据集移除**
  3. 纯值行(无 exp_*)留为正常数据
  4. config.vars 清除 exp_*
- 倾向手动触发(可审可控);不做升级全库自动扫

## 10. 编辑器 IA 汇总

- 数据集编辑器 = 纯值面(§6);断言管理 = 独立编辑器(§7)
- 互跳:条目 anchor ↔ 编排器字段卡;断言面 ↔ 编排器断言卡
- RunDialog:数据集选择(既有)+ 注入条目多选(新),入运行方案

## 11. v1 边界与协议位

协议位(v2+,只留位不实现):其他策略种类(终止/extract)/ 注入 × 数据集矩阵(偏离跑在指定正常行上)/ 多套注入方案 / 值类别快捷与生成器 / 位置寻址(定向未模板化位置)/ 一键模板化 / 偏离入 CSV。
