## 0. 背景与需求追溯

平台已有数据驱动底座(dispatcher 笛卡尔积 + 行 layer + config.vars),但
编排面断言 expected 恒为字面量——负向测试(改输入制造错误、钉住错误表现)
只能一场景一断言,数据集行换不动期望;数据集编辑器以**全场景字段**为列
(行宽 = 字段数 × 140px,8 步 × 5 字段 ≈ 5600px vs 视口 1400px),长过程
用例不可用;扰动字段与断言的因果关联只存在于作者脑中,无处看、无处跳。

## 1. 目标与非目标

**目标**

1. **期望行级化**:断言 expected 可提升为期望变量,数据集行逐行供值
   ——负向数据驱动闭环(正确流程底座 + 扰动矩阵)机制化;
2. **渲染解耦**:数据集网格列作用域收缩到单 step 段,行宽与过程长度解耦;
3. **关联可找**:扰动位 ↔ 期望列双向导航,段内并排呈现;
4. **零机制新增**:引擎、后端、导出链、场景/数据集存储模型零改动,
   全部改动落在前端(编排器 + 数据集编辑器)。

**非目标**

- 运行期动态解析(尺轨禁止,维持);
- 断言结构行级化(target/operator 仍钉死在 strategy,§7 边界);
- 具名断言/行内开关/期望 profile(挂账 §10);
- 数据集单元格取数选择器(挂账 §10,v1.x);
- plate 目录任何变化(golden 零重钉)。

## 2. 场景叙事(负向数据驱动闭环)

```
① 编排器构建正确流程场景(既有能力)
② 在要扰动的请求字段上 ☰ → 设为变量
     body.amount = 100  →  "${var.amount}",基线 100 登记 config.vars
③ 在要钉住错误的断言上 → 设为期望变量
     assertion.expected = 200  →  "${var.exp_code}",基线 200 登记 config.vars
④ 建数据集:段网格里逐行填 扰动值 × 期望值
     data-2 = { amount: -1, exp_code: 400, exp_msg: "金额非法" }
⑤ 跑:不挂数据集 = 全基线 = 正确流程本身(日常回归)
     挂数据集   = 扰动矩阵(数据集×行×repeat 笛卡尔积),断言按行对比
```

同一份场景资产两种跑法——"正确流程底座 + 行级扰动"的机制化。fin SUT
全域同信封 `{code, msg, data}`(取数源 spec 修订 9 实证),负向族与正向族
共享同批断言 target,"同 target 行级换 expected"有现实地基。

## 3. 运行机制(零引擎 / 零后端,全部既有)

### 3.1 既有链实证

- **dispatcher**(既有):`RunRequest.dataSetIds` → 笛卡尔积(数据集×行×
  repeat)→ 行键 layer 进 `config.vars`,**行赢**;`_coerce_row_value`
  按基线类型还原(行 `"400"` + 数字基线 200 → 数字比较);
- **preprocess**(既有,[scenario_preprocessor.py](../../src/gimbal/src/gimbal/preprocessor/scenario_preprocessor.py)
  :438 已实证):root = {service, auth, **var} ——`${var.amount}` 展开
  body、`${var.exp_code}` 展开 Assertion.expected,**同一把伞**;strict
  解析缺键 → ValueError 拒启(期望模板引用的必须是 config.vars
  (-row-layer) 已声明的键);
- **运行期 SpecResolver**(既有):root = {channels, service, auth} 无 var
  命名空间——静态变量(含期望)已烧进字面量,尺轨红线(产物自含/确定/
  可重放)原样成立。

### 3.2 "注入"词义钉住

本设计的绑定**全发生在组合期**(expected 模板 + 数据集行列),运行期
只是既有展开(dispatcher 行 layer + preprocess)。不是 carry_injection,
与运行期注入语义零交集。

## 4. 存储三分(哑数据原则)

| 存储 | 存什么 | 存几份 | 谁写 |
|---|---|---|---|
| `steps[].strategy` | 断言**结构**:kind/target/operator/expected 模板 | 一次 | 编排器 |
| `config.vars` | **列宇宙 + 基线默认**(唯一静态变量声明点) | 每列一行 | 提升动作 |
| `dataset.rows` | **纯数据**(稀疏 dict,缺键 = 继承基线) | 每行一份 | 数据集编辑器 |

**绑定 = var 名单一符号**:`expected: "${var.exp_code}"` ↔ 行键 `exp_code`。
数据集不存策略、不存列元数据、不存分组/期望标记/行产地——全部投影期
派生(凡可从单一真源推导的不第二份存储;与钉值来源不持久化/group 不进
产物同构)。

### 4.1 段派生(编辑器怎么知道列属于哪步)

打开数据集编辑器时对场景做**引用扫描**(纯前端,一次计算):

- step N 的 request body/headers 引用 `${var.y}` → y 是步骤 N 的**输入列**;
- step N 的 strategy 中 `kind=assertion` 且 expected 含 `${var.exp_x}`
  → exp_x 是步骤 N 的**期望列**(顺带取 target/operator 供列头徽标);
- 多段引用同名 var → **共享列**,各段重复出现 + "共享"徽标(特性非缺陷);
- var 作用域 = **整个场景**(config.vars 场景级,无 per-step/per-service
  命名空间):跨服务步骤引用同名 var = 共享同一值(跨服务穿线的正当
  形态);"各服务要各值"是命名问题——提升时起不同 var 名,行里即成
  两列。

### 4.2 引用扫描与 ${var} 的值域

`extract` 产出与 `assign` 注入走运行期通道(channels/scratch),preprocess
期不存在——期望/输入模板引用的键必须在 config.vars 中已声明,否则
strict 解析拒启(§3.1)。因此列宇宙天然闭合于 config.vars,老数据集
(行键 = var 名)自动兼容。

### 4.3 关联关系的本质(需求 #3 的正面回答)

```
型级关联(场景里,派生):步骤N 段 = 扰动位 {amount} + 期望 {exp_code, exp_msg}
量级关联(数据集里,数据):data-2 行 = {amount:-1} × {exp_code:400, exp_msg:"金额非法"}
                          ↑ 这一行就是一次"哪个字段导致了什么断言"的完整记录
```

关联**已经**维护在数据集里——不是元数据,而是每行的数据本身。**不存
第三份显式链接表**:字段改名/断言删除必漂移;多输入组合驱动同一期望时
(amount 与 policy_id 一起才触发 400),成对链接变成没人维护的图。更细的
因果配对只有作者知道,行数据已携带,框架不假装知道——**导航粒度诚实
地停在"同步骤"**(§5.3)。

## 5. 编排器侧改动

### 5.1 扰动位(既有机制正名,零新通路)

"设为变量"就是输入字段的模板化替换(body 字段 → `${var.字段名}` +
原值登记 config.vars)。增量的只有**身份呈现**:提升后的输入字段行挂
"扰动位"徽标(替代裸 var 徽标的语义升级)。

**多视图前移提示**(2026-09-10 评审补):同名字段提升复用既有 var 时,
若本字段 value_source 与既有引用字段的视图不一致 → 软提示"同 var 多
视图,数据集查钮将退化手输(§8.4)",可继续——把 §8.4 守卫的显形时机
从数据集填值期前移到提升期(治理口诀:共享 var 就统一视图绑定,
"同值 ⟺ 同源"对齐)。

### 5.2 期望变量提升(本设计唯一的策略面新增)

断言卡 expected 值旁新增"设为期望变量"动作:

- `expected: 200 → "${var.exp_code}"`,基线 200 登记 `config.vars`;
- **命名 = `exp_` + target 末段**(`$.response_body.code → exp_code`;
  `$.response_status → exp_status`);撞名 → 对话框提示改名,不静默
  `_2` 后缀;
- **逆动作(还原)**:expected 写回基线字面量 + config.vars 删键;有
  数据集行引用该键时软提示"行数据将成死键"(可继续);
- 前缀只是**意图声明,不是命名空间**:手写 `${var.exp_x}` 进 body 会被
  引用扫描正确归为输入列;VarSelector 候选里 exp_* 标注"期望变量"防
  误用(**标注不禁选**——同值既输入又期望的双用合法)。

### 5.3 双向导航(需求 #4)

- **期望列头 → 断言卡直跳**:数据集编辑器期望列头徽标带 target/operator
  (tooltip 全量),点击跳编排器对应断言卡——路由携带 stepIdx +
  strategyIdx,编排器挂载后定位 `#strategy-card-N` + sf-flash(B4 既有
  通路复用);
- **编排器反向**:断言卡 expected 挂"期望列"徽标,点击跳数据集编辑器;
  断言卡显示"**同步骤扰动位**:amount、policy_id"(诚实粒度 = 同步骤);
- **可选糖**(v1 可省):输入字段扰动位徽标 hover 显示覆盖统计(被几个
  数据集多少行引用)。

## 8. SUT 请求数据边界(需求 #11)

### 8.1 三权分立:座位 / 查法 / 值(绑定控制问题的正面回答)

SUT 请来的数据进数据集,**绑定关系不在数据集里**——三权各归其位:

| 权 | 持有者 | 形态 | 产生于 |
|---|---|---|---|
| **座位**(哪里要值) | 场景 steps | `${var.customer_id}` 模板引用 | 编排侧提升动作 |
| **查法**(怎么查值) | plate 目录 | 字段声明 `value_source{view, column, group}` | 目录发版(绑定是共识→发版,取数源 §3.6) |
| **值**(具体是什么) | 数据集 rows | 行键 = var 名,标量 | 行编辑期(手输/粘贴/查选) |

- **绑定控制永远在编排侧**:座位(`${var}` 引用)是唯一绑定;数据集不
  定义绑定、不定义字段路径、不持有映射——**行键 = var 名是唯一匹配
  符号**(§4 join key);
- 数据集编辑器若提供查选(§8.4),查法是**推导来的**:var 名 → 反查
  引用该 var 的场景字段 → 读字段声明上的 value_source——目录同一份
  绑定的第二次消费,不是数据集自己的第二套;
- **否决"数据集内字段路径定义匹配"形态**(评审留痕):数据集持有
  path → SUT 数据的映射 = 场景 var 引用之外的第二份绑定,双源必漂移
  (§4.3 同理);且行值若在执行期才按路径解析 = 运行期动态解析,尺轨
  红线禁止——若编辑期解析后钉标量则等价于本方案,白多一层映射,零收益。

### 8.2 两形分轴(运行边界)

与取数源 §13.6-4 同口径(**组合期取数用查询,运行期联动用变量**):

| 形 | 机制 | 归数据集管吗 |
|---|---|---|
| 组合期查的(取数选择器钉的字面量) | value_source 查→选→钉 | **值可以进,来源不进** |
| 运行期活的(extract 重查) | 方案一机制 | **不归**——行只覆盖静态变量(preprocess 期),extract 写运行期通道,两轴互不干扰 |

组合期钉的值 = 普通标量:**编排侧查钮照旧**(查→选→钉基线字面量,零
变化);提升为扰动位后,数据集行换值 = 换一组 SUT 数据的占用。数据集
**不记录值从哪个视图查来**(与钉值来源不持久化同款纪律)。

### 8.3 行 = 组(三个共用形态)

1. **多字段一组**:一查多填的列(customer_id + customer_name +
   client_expand_*)在同一步段并排,**同一行的这些列 = 一组**;
2. **跨行/跨数据集共用**:复制行(复制制,裁定);
3. **执行时挑选携带**:**行就是执行单元**——dispatcher 每行独立执行一次,
   行内键值即本次执行携带的数据;"选哪组" = 行里填哪组值,无需执行期
   挑选机制。行引用具名组(写 `组=客户A` 而非逐列填)= **输入 profile**,
   与期望 profile 同票挂账(§10)。

### 8.4 单元格查选(挂账 v1.x 糖)

数据集编辑器单元格嵌取数选择器:**推导链 = var 名 → 引用该 var 的场景
字段 → 字段声明上的 value_source**(§8.1 三权分立的第二次消费),复用
ValueSourcePicker 提供"查"钮,**选行扇出填本行同组多列**(与编排器一查
多填同构,机制 100% 复用,落点从 body 换成 row)。歧义守卫:同 var 被
多个不同 value_source 的字段引用,**或引用字段跨服务域**(查询上下文
锚定引用字段的 step 服务域——修订 10 域内首键同款;推不出唯一域即
命中守卫)→ 该列不出查钮(手输不受影响;推导链有一丝歧义即退化
手输,绝不猜)。另:扇出天然不跨服务——group 一致性(取数源 §3.3⑥)
锁同组字段于同一 view ⊆ 同一端点 ⊆ 同一服务。

**多 var 同源**(2026-09-10 评审补):同 view 被多个 var 占用(同系统
两用户,各模板化为 `customer_id_1` / `customer_id_2`)是合法形态,
**不命中守卫**——守卫只管 var→value_source 方向的多值;反向多 var 同一
value_source = 两次独立业务占用,各列独立出查钮、独立选行、独立写入。
**视图列名是取值键(`row[column]`),不是写入键**;写入目标 = 点查钮那列
的 var 名。**扇出作用域 = 该 var 的推导闭包**(引用字段 → 同 group 兄弟
声明 → 兄弟在**同引用段**模板化的 var 列)——同端点同字段跨步仅一份
目录声明,group 拆不出两个身份(取数源 sender/receiver 是同表单两个字
段的拆法,不适用),故扇出必须按 var 推导闭包锚定引用段划界,不得按
group 声明全局划界;跨 var 的同名占用不在扇出路径上,不被误写。两列查
同一 view = 同一行集快照(缓存共享),A 列选 X、B 列选 Y = 两用户交叉
组合的数据驱动形态;查询凭证为域内首键视角,为用户 B 的列选的值 B 未必
可见——§6.3 断言兜底,口径不变。

**扇出前提 = 组内字段已提升**(2026-09-10 评审补):一查多填"哪个返回
字段进哪列"由目录 value_source{column, group} **预声明**(非查询时从
响应发现),复用编排器既有机制零新增;组内只提升部分字段时,扇出仅写
已提升列(列存在才有落位),未提升兄弟保持编排期字面量、不随行变(取数
源 §13.6-4 链条一致性冻结口径)——要行级一致 = 整组提升,或走运行期
联动轴(extract→var→assign)。查询返回但目录未绑定的字段不进投影列集
(label ∪ 绑定列,取数源 §4.2):临时用走手输逃逸门,长期用走目录发版
加绑定(绑定是共识→发版,取数源 §3.6)。

**同 var 多视图的守卫 rationale 与解除路径**(2026-09-10 评审补):var 名
= "同值"声明,多视图 = 多份"从哪查"声明——框架无信息裁决两视图值域
是否互换(X 查回的 id 接口 B 认不认,只有作者知道),故不猜。解除:
①**目录统一**:值域确同源的两端点字段绑同一视图(绑定是共识→发版,
取数源 §3.6),推导恢复唯一,查钮回来——查询声明漂移在目录修;②**命名
拆分**:各要各值 → 拆 var 名(§4.1),各自单引用各自出查钮;③**手输**
(逃逸门恒开)。编排器查钮锚字段不锚 var、运行期 value_source 零参与,
两面均不受多视图影响(§8.2 既有口径)。若守卫命中成为高频痛点,可升级
为多视图选择(点查列出候选视图,作者挑)——触发器驱动,暂不立项。
v1 手输/粘贴已闭合工作流,故不进主线。

### 8.5 查询视角与多用户权限(2026-09-10 评审补)

多用户编排(同系统多用户 / 多系统多用户)机制面全支撑:每步各挂各的
执行身份(headers `${auth.<tag>.token}`)、各用户各值拆 var(§4.1)、
行携带多用户值、运行期按步展开零改动(§3);跨域查询隔离 = 修订 10
零命中诚实 null。**软肋 = 查询候选的权限视角**:查询身份 = 域内首键
(修订 10)——同域多用户时,所有查选(编排器查钮 + 本节糖)都以首键
用户的可见性行事;为首键可见、为用户 B 不可见的值选进 B 的列,执行时
由 B 的请求失败暴露(§6.3 断言兜底)。构造消解(查询用执行账号 → 钉的
值执行时必然查得,修订 8)仅在"每域单用户"时成立,域内多用户降级为
断言兜底——不炸,但保证降级。

**升级票(拟取数源修订 11,待裁定)**:查询身份锚定 step 实际引用的
auth tag(headers `${auth.<tag>.token}` 首命中——它就是该步执行身份,
查询视角 = 执行视角;无引用 → 域内首键 fallback,单用户场景零变化);
配套 L1 缓存与单飞键从 view 扩为 **(view, 查询凭证)**(否则 A 先查、
B 吃 A 的缓存,权限视角在缓存层串台)。落点:取数源 §6.1/§5.1 +
runner 缓存键 + composer/糖 queryAlias 推导——**后端触碰,不入本
计划**(§1 零后端目标不变),在取数源语境独立实施。
