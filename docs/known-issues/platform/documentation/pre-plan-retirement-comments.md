# 计划之前发生的退场仍靠代码注释承载（ADR-0003 的补录是**独立工作**）

> **模块**：`docs/adr/0003-retired-features-log.md`（约定）× 代码注释（现状）
> **状态**：已知未修复（**独立工作项**，不是本轮遗漏）
> **来源**：架构收敛执行会话自查（非 spec 条目）

---

## 0. 约定是什么

ADR-0003 把退场知识的归宿定成**唯一一处**：

> 本文件是**退场知识的唯一归宿**：功能退场后，代码注释不再承载「已移除/已退场/原为 XX」类历史叙述，统一收录于此。代码中的注释只描述当前行为；需要追溯历史时查本表与所引 spec/commit。
> （`docs/adr/0003-retired-features-log.md` 文件头）

但它的**维护约定是前瞻的**（同文件末尾）：

> - **此后**退场某功能时：删除代码（含注释），并在本表追加一行 + 详情小节（日期 / 原语义 / 现语义 / 存量处置 / 提交）。
> - 代码注释一律现在时描述当前行为；历史性对照（「原为 / 已移除 / 已退场」）只写在本文档。

「此后」= 从该约定生效起。**在此之前发生的退场没有补录**，于是留下一个不对称：注释里写着历史，而本表里没有对应行 —— 追溯时没有归宿。

## 2. 为什么它是**独立工作**，不是本轮遗漏

1. **约定的时间边界**：ADR-0003 的规则是前瞻的（「此后」），旧退场不在其覆盖内 —— 不补录**不违反**约定，只是留下空白；
2. **补录需要逐条考据**：每条都要给出「日期 / 原语义 / 现语义 / 存量处置 / 提交」五项（见 ADR-0003 的详情小节格式），这需要逐个退场回溯提交与 spec，属**一轮独立工作**；
3. **归属**：`docs/adr/**` 由**别的任务**所有（本记录只登记，不代改）。

**正确的顺序**（避免先删注释再丢知识）：

1. 先把旧退场的行补进 ADR-0003（考据 + 五要素）；
2. **再**清理代码注释里的历史叙述（只留现在时）。

反过来做（先删注释）会**真的丢掉**那些退场知识 —— 因为今天它们**只**存在于注释里（本表无行）。

---

## 3. 优先级：P2

按 README：**结构性 / 风格性 / 可维护性问题，不影响功能**。

- 不影响任何运行时行为；
- 影响的是**知识可追溯性**：今天追溯 2026-08 的退场只能靠 `git log` / blame，而项目的既定纪律要求看 ADR-0003；
- 随时间的代价会**变大**：越晚补录，回溯成本越高（本记录本身就是一次「已经需要 blame 才能定位」的例子）。

---

## 4. 何时重开

1. **有人要追溯一次旧退场**（例如「chips 为什么没了」）而 ADR-0003 查不到 —— 那一刻即本章的价值兑现点，也只能那一刻付考据成本；
2. **做 ADR-0003 的整理轮**：把「行只覆盖 2026-09-09 起」这一事实显式写进本表的说明里（一句注记即可让读者知道边界，而不是以为「表里没有 = 从未退场」）—— 这是**成本最低**的一步；
3. **同一文件再次被改动**（例如再动 `RunDialog.vue`）：按纪律，那时的退场要**即时**补行，不要累积；
4. **评审/审计提出「注释里为何有历史叙述」** —— 本记录是标准答复（「ADR-0003 的边界在此，补录是独立工作」）。
