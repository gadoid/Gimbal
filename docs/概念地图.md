# 概念地图（一页纸 · 新成员入口）

> 三栏对照：每个概念一句定义 + 代码入口。2026-10-14 建档。
> 深入阅读顺序：`docs/architecture.md` → `claude/plate-version-model.md` → `docs/系统接入运行手册.md`。

## ① plate（接口契约的版本管理）

| 概念 | 一句话定义 | 代码入口 |
|---|---|---|
| 系统（system） | 一个被测系统的接口契约树，`systems/<sys>/` 目录 | `systems/fin/system.md` |
| 端点（endpoint） | 一个接口的契约（方法/路径/字段/认证声明） | `systems/fin/endpoints/*.md` |
| 修订（revision） | 系统树某次签发的快照，`<line>#<n>`（如 `1.0#2`） | `src/gimbal_plate/release/` |
| working | 未发版的当前规格树（预览执行口径） | `src/gimbal_plate/registry/` |
| M2 | 场景/步骤的类型契约（生成物，代际管理） | `src/gimbal/schema/_m2.py`（生成）、`scripts/gen_m2.py`（生成器） |
| convert | 平台场景 → 引擎可执行形态的校验+投影 | `src/gimbal_plate/http/routes_grammar.py` |
| 构件分支 | `plate/artifacts` 孤子分支，修订快照与 M2 信封的存储 | worktree `D:\Gimbal\plate-artifacts` |
| 外部锚点 `ext:` | 平台目录登记的第三方接口（不走 plate 版本） | `external_endpoints` 表 + `X1` 导入器 |

## ② 平台（ gimbal-platform，场景编排与执行调度）

| 概念 | 一句话定义 | 代码入口 |
|---|---|---|
| 场景（scenario） | 一份可执行的业务流定义（M2 实例 + orchestration 容器） | `app/services/scenario_store.py` |
| meta.plate | 场景的版本声明：每个归属系统钉修订或 working | 保存闸 `enforce_meta_plate` |
| 锚点步骤 | 声明了 `step.endpoint` 的步骤，binding 派生字段由 convert 投影 | `scenario_store.strip_binding_fields` |
| 数据集 / 注入条目 | 数据驱动行 × 判例偏离（assertion_registry） | `app/services/run_injection.py` |
| 执行（execution） | 一次发起的调度单元（行 × 重复），终态 done/failed/canceled | `app/services/run_dispatcher.py` |
| server 链 | 默认执行链：平台 → 引擎 server 实例池（HTTP） | `app/services/gimbal_server_session.py` |
| 入库基线（baseline） | 版本模型 4.3 判定：钉修订+全评审才计入基线 | `executions.baseline_*` 列 |
| 变更适配 | 系统发新修订后，场景按差异切换声明的流程 | `app/services/adaptation_service.py` |
| Suite | 用例集（graph 编排成员场景，版本模型求交） | `app/services/suite_version.py` |
| 凭证（auth session） | 服务认证凭据，Fernet 加密存储 | `app/models/auth_session.py` |

## ③ 执行器（gimbal，引擎）

| 概念 | 一句话定义 | 代码入口 |
|---|---|---|
| 引擎 | 装配 case → 驱动步骤 → 出报告的运行时 | `src/gimbal/core/runner.py` |
| 认证施加（auth） | 按声明把凭据注入请求（声明驱动，gen2） | `src/gimbal/auth/` |
| 策略（strategy） | 步骤上的断言/赋值（assertion/assign） | `src/gimbal/strategy/` |
| error_kind | 每步失败的结构化分类（auth/transport/…） | `runner._error_kind_of` |
| CLI | `gimbal run launch/server`，退出码即结果信号 | `src/gimbal/cli/` |

## 三者如何连起来（主链路）

```
编排器(UI) ──保存──▶ 平台场景库(PG)          [保存闸: meta.plate 强制 + 视图键剥除]
    └─发起运行─▶ run_dispatcher ──/convert──▶ plate(按 meta.plate 取修订/working 投影)
                      └─case.json──▶ gimbal 引擎(server 链/子进程) ──▶ 真实被测系统
                          └─事件/行/工件──▶ 平台执行详情(失败原因首屏化)
```
