## §1 背景与目标

### 1.1 剩余问题(v2 修订:泄漏面已关,治理面仍在)

前轮已收口的泄漏面:公共发布剥凭证(S1.3)、非属主读面剥 users(W6)、
跨属主拷贝/fork/suite fork 剥凭证(copy_scenario 单点)、导入落库清空
config.users + authRefs 对照本人池(P2)。**场景快照已经只服务属主自跑**。

仍在的治理缺口:

- **手填明文仍落场景库**:UsersCard 手动配置明文写 `config.users`
  (`UsersCard.vue:3`),凭证以明文散落在私有场景 payload 里,池外无治理;
- **快照 = 陈旧值静默生效**:属主自跑时,名字不在池、也无别名绑定的引用
  静默用快照旧值——测试建立在过期凭证上不自知(与 FE-02 假空态同类:
  治理依据失真);
- **双份数据**:快照拷贝与池解耦,轮换要逐场景重导;反查 snapshot 类
  卫生信号常年非零;
- **配置入口没有池过滤**:手填/导入不校验凭证与槽位服务的关系,
  错配在执行期才显形。

### 1.2 目标

- 新场景凭证只落池(Fernet 加密),场景里只存条目名引用;
- 槽位声明(条目 = 服务-环境-调用身份要求)全局可见(现状已有),
  凭证本体保持池私有;
- 配置页双入口:检索池(scope 过滤,本人 + 项目双源)+ 手配
  (手配落池为新凭证);**消灭「场景私有凭证」第三种形态**;
- 引用真实性由决策 1 的登记闸保证(保存/导入时 422),本案只管
  凭证集中与候选过滤——两案分层见 §10。

### 1.3 非目标(维持 v1)

- 导出产物如何使用、CLI 独立执行如何校验凭证——不设卡点;
- plate schema(`Config.users` 是执行器输入契约)不动;
- 存量场景数据不静默修改(只对新建生效,§7)。

### 1.4 结构图景(维持 v1,凭证行状态改「本案补全」)

| 维度 | 模板来源 | 场景引用形态 | 状态 |
|---|---|---|---|
| 接口 | plate 方言定义 | 步骤锚定 endpoint,call 只存 service/user/path_params | 已是 |
| 域名 | 环境实例 login_url / 部署表 API 地址(别名 base_url 语义已退役为部署表) | 显式绑定 > authored 声明 > 环境 | 已是 |
| 凭证 | 凭证池(本人 / 项目,双池已建成) | 名字引用 + scope 过滤 | **本案补全** |
| 字段值 | carry 绑定 / 数据集 | 填缺失注入 | 已是 |

组装点 = `materialize_run_copy`,五入口同源;「模板供默认、显式值优先」,
唯独凭证变纯引用无字面逃生口——敏感性不同的不对称是有原则的。

## §3 改造方案(本期)

### 3.1 核心不变量(维持 v1)

凭证只落池、场景只存名字;全局可见的是「槽位要什么身份」,私有的
是「我的身份是什么」。名字引用语义保留(可迁移性来源)。登记(条目)
与持凭证(池)分离——**引用不要求执行者当下持有凭证,缺凭证在预检/
执行期显形**,草稿可以先写引用后配凭证。

### 3.2 scope = 复用 system 列(零迁移,v2 修订)

- **不新增归属列**:`AuthAccount.system` 即服务归属(条目侧经
  base_service→services.system 派生对齐,两侧同键);
- 匹配规则:检索/候选 = 池 ∩ system 匹配条目系统名;url/token_type
  不做硬校验(登录域与服务端点常不同域);
- 槽位要求语义(「该条目需要哪个系统的凭证」)由条目自身的
  base_service 链派生,别名表无需加列;
- 跨服务通用凭证(统一认证中心):现状每行单 system —— 同密多行
  即可表达,**不引入「不限」空值语义**(见 §9 待拍板)。

### 3.3 UsersCard 双入口(表单字段按现模型修正)

- **检索**:按条目/系统检索池(scope 过滤),选中即引用,场景只存名。
  检索源 = 多源带徽标,**双源(我的 + 项目池)进本期拍板**(v1 视为
  后续——项目池已建成,只缺检索面,§9);
- **手配**:填 (system, env, username, password, account_fields…)
  ——**无 url**(登录口属环境实例)、无 token_type/expires_in(引擎
  侧按签名器/会话处理);保存即新凭证入本人池(Fernet),场景存名;
- 同名冲突不静默覆盖(§3.4);手配进池后是普通池凭证,任何场景可检索;
- `config.users` 不落明文快照,不发明第三种存储形态。

### 3.4 行为规则(维持 v1 四条,建议照默认定档)

1. 同名冲突:提示「直接引用 / 去认证管理修改」,不覆盖;
2. 编辑已引用行 = 改池本体,显形爆炸半径「影响另外 N 处引用」
   (auth_references 计数现成);
3. 删除行 = 只移除引用,不删池凭证;凭证删除仍走认证管理拦截;
4. 落池随场景保存同事务,保存结果列出本次新建凭证
   (连带触发 revive_paused_instances,见 §4.4)。

### 3.5 保存闸:场景侧 config.users 收口(v2 新增,补 v1 漏项)

- 新场景保存/更新(scenario_store create/update)对 definition.config
  .users 非空 → **422 `plaintext_users_rejected`**,detail 指引
  「引用改为条目名;手配凭证走认证管理或配置页手配落池」;
- 选 422 而非 strip:静默丢弃用户输入是假空态反模式,且与决策 1
  「闸失效最坏退化为现状」哲学一致;
- 直写 API 绕不过;存量场景(§7)不受影响(只对新建生效的判定点
  = 场景创建时间,不改存量行);
- 与决策 1 登记闸同一调用链:`unregistered_identities`(引用是真的)
  与 `plaintext_users_rejected`(不带明文)一前一后。

### 3.6 查询视图联动(唯一硬联动点,维持 v1)

前端身份选择换数据源:从池拿 url 做同域判定,替代 authored
config.users(`CaseComposerCanvas.vue` resolveQueryContext/queryAliasOf);
后端 loader 不动。config.users 清空方案下不改则组合期取数诚实返回空。

### 3.7 TOK-05 护栏接力(v2 新增)

TOK-05(2026-11-20)按「拍板保留 + 护栏」给明文快照加了审计行 +
导入二次确认。本案落成后:

- UsersCard 快照导入入口整体退役,二次确认闸随之删除;
- `auth.secret.read` 审计动作**保留**,继续服务认证管理页明文查看;
- 这是「护栏过渡 → 结构性收口」的既定接力,不是推翻拍板。

### 3.8 admin 跨属主规则(维持 v1)

保存者 == 场景属主才开放 inline 新建;admin 改他人场景只能手填名字
(名字引用本就按执行者解析)或留给属主;不开跨 owner 写池路径。

## §10 与决策 1 的合并实施路线
